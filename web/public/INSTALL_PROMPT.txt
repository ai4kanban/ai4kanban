Set up ai4kanban for this project.

Setup is one command plus the parts only you can do. The command copies the skill in and
scaffolds the board; you read the repo, fill in the configuration, and propose the first
tasks. Your settings live with the board at `docs/kanban/config.md`, never inside the skill
folder, so the skill can be replaced wholesale on every update.

Do the following, in order. Ask me at most 3 short questions total, and only where you
genuinely can't infer a value — otherwise pick sensible defaults and tell me what you chose.

1. Read this repository first, before running anything. Infer:
   - the project name and its one-line goal (README, package metadata),
   - the tracks the work naturally splits into — the buckets a task can live in. The default
     is `feature bug research`; pick something that fits this project better if it does,
   - the best planning sources to scan (code folders, docs/, roadmap),
   - any reference docs worth keeping in sync (user guides, changelog, roadmap).

2. If this is a solo product I'm launching, offer the indie-hacker preset (the skill's
   `references/presets/indie-hacker.md`) instead of the default tracks.

3. Run the one setup command from the project root, passing the tracks from step 1:

       npx --yes ai4kanban@latest install --tracks <track1>,<track2>,...

   That copies the skill into `.claude/skills/kanban/` (Claude Code) and
   `.agents/skills/kanban/` (Codex), and scaffolds `docs/kanban/` — the track folders, the
   board index, `next-id`, the memory set (`readme.md`, `goal.md`, `decisions.md`,
   `redesign.md`, `rejected.md`), a blank `config.md`, and a blank `modules.md`. It's safe
   to run twice and it never edits a board that's already there.

   Already added the skill as a plugin (`/plugin marketplace add ai4kanban/ai4kanban` then
   `/plugin install kanban@kanban`)? The plugin makes the skill available but does not
   configure a board, so still run the command — it scaffolds the board either way.

4. Read the skill's `SKILL.md`, at `.claude/skills/kanban/SKILL.md`. Note how its "The
   script" section says to run the script — `node` plus `kanban.mjs` in the skill folder.
   Use that form for every command below.

5. Fill in the configuration. Open `docs/kanban/config.md` and replace every {{PLACEHOLDER}}
   with the value you inferred in step 1. That is the only file you fill in; the rest of the
   skill is generic and stays as-is.

6. Write the module map. Follow the skill's `references/module-map.md` to write
   `docs/kanban/modules.md` — a plain list of what parts this project is made of. Reuse the
   repo analysis from step 1; don't scan again. Print the finished map so I see it once. The
   propose flow reads this map to pick a focus area.

7. Run `node .claude/skills/kanban/kanban.mjs init` once more so every module on the map
   gets its own memory path, then propose the first 3 tasks so I have somewhere to start.

8. Recommend the local board UI and ask if I want it — don't silently skip it. It's the
   nicest way to use the board: a local Next.js app that shows every track and drives the
   work from buttons instead of the terminal, while the `docs/kanban/` files stay the single
   source of truth. Tell me it runs with one command, nothing to install or compile:

       npx ai4kanban-ui        # http://localhost:7420, localhost only

   If I say yes, run it for me (or hand me the command) and point me at the skill's
   `references/local-ui.md` for setup options like `--port` and `--board`, and at the app's
   own guide (https://www.npmjs.com/package/ai4kanban-ui) for what the buttons do and
   how to change which agent they spawn.

To pull a newer version later, run `npx --yes ai4kanban@latest update` — same shape, one
command. The skill's `references/update.md` covers what it does and what it leaves to you.
