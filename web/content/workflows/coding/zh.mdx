## 你要把关的，往往就是几个关键点。

做一个功能时，你可能想先把关界面原型、Agent 指令、宣传文案或邮件内容。这些关键点对了，你才愿意让 Agent 继续实现。

想法一句话就能说清，做出来却总要改同几个地方。AI4Kanban 让 Agent 提前出草稿，把需要你决定的问题放到任务卡片上。

你在卡片里审阅和修改，定下的决定写进计划，Agent 按计划继续做。

## 不确定要不要？先看草稿再决定。

你可能只是想试试：给产品加一个邀请入口，会不会让页面更复杂？如果等整套功能做完才看，发现不合适，已经写好的页面、接口和测试都可能需要撤回。

在 AI4Kanban 里，可以先看邀请页面的原型，以及任务需要的邮件草稿。你觉得不对，就修改计划；觉得不值得做，就否决这个方向。判断不必等到完整功能实现之后。

## 每个任务单独预览，不必一直开着项目。

直接看开发中的页面，得先把项目跑起来；代码还没改完，页面可能就打不开。

AI4Kanban 在任务卡片中直接预览静态 HTML/TSX 草稿，分别看手机和电脑双端原型。不用启动项目或接好后端，每个任务都能独立预览。

## 需要你决定的问题，提前问清。

草稿之外，还有影响功能的关键规则。比如邀请成员时，新成员默认有哪些权限？Agent 会把这类问题和选项放到卡片里，供你直接回答。

你不必从头写完整需求。Agent 结合项目补齐计划，只把需要你作决定的地方提出来。

## 每个关键点，都有对应的 Agent 负责草稿。

编码工作流已经配好专业 Agent，按任务需要参与。

- **界面设计师**：画出页面、交互和空白或错误状态，提供手机和电脑双端原型。
- **提示词撰写**：用 diff 展示 Skill 或 Agent 指令的具体修改。
- **文案与文档**：写出官网、README、版本说明和用户文档的文案。
- **邮件策划**：准备邮件标题与正文，提供手机和电脑预览。

## 这次说清楚，下次少重复。

每个 Agent 有自己的记忆，保留能指导后续工作的偏好和纠正。比如文案 Agent 记得「同一主题只讲一次」，邮件 Agent 记得「第一句就说清读者要做的事」。

下次起草时，对应的 Agent 会读取这些记忆，减少你重复纠正。

## 主线功能做完，Agent 帮你查缺补漏。

主线功能完成后，Agent 会提出跟进建议。后台 Agent 回顾进展，质检员从用户角度测试近期改动，帮你找出遗漏。

对邀请功能来说，建议可能涉及错误状态或缺少的测试。建议进入待筛选列表，由你决定是否建成任务、继续讨论或忽略。

## 小修复轻量完成，大任务先把方向定好。

2026 年 10 月的单次、小样本无人值守实测中，AI4Kanban 开发流程的费用是直接用 Claude Code 的 1.07–2.08 倍，不含后台 QA。

简单修复只多花约 7%–12%，验收得分接近直接使用 Claude Code。大任务则通过拆解、草稿和澄清，让你提前把关关键决定，减少方向性返工。

## 继续使用你已有的编码工具。

在桌面应用里打开现有项目，连接[受支持的编码工具](/docs/connectors)，例如 Claude Code 或 Codex。工具在你的电脑上运行，使用你自己的订阅；AI4Kanban 不额外收取 token 费用。

每个 Agent 可以分别选择编码工具和模型。你也可以通过 Skill 和 CLI，在编码 Agent 会话中操作同一个看板。支持范围与配置方式见设置和 Agent 指南。
