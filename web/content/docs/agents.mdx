Every flow on the board is run by a named **agent**. Each one has a page where you set its rule,
what it runs on and, for a scheduled one, how often it runs. **Configuration → Workflows** lists
each workflow's agents; **Configuration → Board** lists the ones the board runs for every workflow.

Product video, Slide deck, Carousel post and Blog post need a Pro plan. Coding and the workflows
you make yourself are free.

## Roles

Roles run the board's own flows. You can't add, remove or switch one off.

- **Software planner** — plans the Coding workflow's cards: create, refine, resolve, revise,
  release plans and changelogs.
- **Builder** — builds a card and lands it.
- **Scriptwriter** — writes a Product video's script; you approve it before the film is made.
- **Deck planner** — plans a Slide deck: you approve the content, then get an editable `.pptx`.
- **Carousel planner** — plans a multi-page post for Xiaohongshu, Instagram, LinkedIn or TikTok:
  you approve the copy, then get every page as an image with captions.
- **Blog planner** — plans a Blog post: you approve the outline, then get the full article with
  its images.
- **Proposer** — after a card is archived, proposes the work that should follow it into
  [Triage](/docs/triage).
- **Review chats** — after a card is archived, reads its chat and writes down what it settled.
- **Describe the project** — keeps `docs/kanban/memory/project.md` — what the project is and who
  it is for — up to date. Planning reads it for direction.
- **Memory pruner** — trims the memory back to what helps planning.

## Specialists

A specialist writes one section of a card while it is planned, and changes nothing else. The
planner calls one in when the card needs it, so you rarely ask yourself. When the answer is a
choice only you can make, it leaves an open question on the card.

- **`copywriting`** — promotional copy: website pages, the README, release notes, store listings.
- **`ui-designer`** — a mockup of each screen the card changes.
- **`tech-stack-advisor`** — compares the libraries, tools or services a card could use, and
  picks one.
- **`prompt-writer`** — instructions an AI model follows: skills and agent prompts.
- **`email-planner`** — every email the card adds or changes, previewed on desktop and mobile.
- **`user-docs`** — the user documentation the card changes.
- **`demo-rehearser`** — Product video only: rehearses each demo for real and shows the results.
- **`hyperframes-editor`** — Product video only: makes the film once you approve the script.
- **`cover-designer`** — Product video only: makes the video's cover.
- **`blog-illustrator`** — Blog post only: makes the post's cover and images.

To ask for one yourself, say **"put the ui-designer agent on #4"** or run
`akb spec ui-designer 4`. Which specialists a workflow uses is set in its plan stage under
**Configuration → Workflows**.

## Give an agent a rule

A **rule** is a paragraph in your own words that the agent reads on every run. Write it in the
box on the agent's page. It is saved to `docs/kanban/rules/<agent>.md`, so git shares it with
your team. Keep it short — every run reads it.

## What agents remember

Some agents remember your corrections and choices, so their next plan starts from them. An
agent's page lists its memory files, kept in `docs/kanban/memory/agents/<agent>/`; edit them
like any other file.

## Let the memory review remember for you

Chats don't save memory as you talk. Once a card is archived, **Review chats** reads its whole
chat once and writes down what lasted. Say "don't record this" in the chat and nothing is
written. **Review now** on its page runs one at any time.

## Run an agent on a schedule

Scheduled agents run by themselves, on no card: the board's own under **Configuration → Board**,
and each workflow's under **Scheduled** in **Configuration → Workflows**. Coding ships one, the
[QA manager](/docs/daily-loop#test-cases).

- **Choose how often**: on the agent's page pick **Auto** — it runs when there is something new
  for it — a preset, or your own schedule. **Disable** turns it off.
- **Run now**: starts one at any time, even while it is disabled.
- **Its changes are committed** like a build when **Automatic Git commits** is on.
- **A failed run is tried again later**, or **Resume** it from **Runs**.

From a terminal: `akb workflow schedule <id> --on <agent> --cadence 1d` (or `auto`),
`--off <agent>`, or `--run <agent>`.

## Add one of your own

Ask your coding agent, with the [AI4Kanban skill](/docs/daily-loop) installed:

```text
Use the AI4Kanban skill. Read akb guide write-agent,
then create an agent that [describe its job].
```

Or press **+** beside **Helpers** or under **Scheduled** in **Configuration → Workflows**, name
it, and write its instructions on its page. A **helper** joins planning on the cards it fits; a
**scheduled** agent runs by itself.

**Delete** on its page removes an agent you added, with its rule and memory.

## Choose what an agent runs on

Each agent's page picks its runtime — the coding tool and model it runs. See
[Runs](/docs/runs#which-runtime-each-agent-runs-on).
