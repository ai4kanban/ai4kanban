Everything in [the daily loop](/docs/daily-loop) is a card. The rest of what the board app's
buttons do can be asked for just as plainly, and your agent runs the matching command — the
runs panel and `akb run` are the same list either way.

| You say | What happens |
| --- | --- |
| "what's running?" | the runs going now, and what ran lately |
| "show me that run's log" | its log, or `--follow` to watch it go |
| "stop it" | the run ends, along with every command it started, and the card comes back |
| "that run died — carry on" | it resumes where the agent left off |
| "that run never got going — try again" | **Retry** starts the same ask again |
| "use Codex instead" / "switch to Opus" | the board's agent, model, reasoning effort |
| "check my setup works" | one small message through the setup, so a bad login turns up here rather than on your next card |
| "save my API key" | it hands **you** the command to type yourself, so the key stays out of its transcript |

When an ask can't run, the answer names the one line that fixes it.

If card creation fails or stops, choose **Resume creating** or **Discard** on the board. Discard
moves the unfinished card to the archive, marked **Rejected**.

Runs, logs and chats are kept on your machine, not in the repository. Move or rename the project
and its board starts with an empty run history.

## Sub-runs

An agent inside a run can hand part of its work to a **sub-run** with `akb run start "<task>"`
— the [QA manager](/docs/daily-loop#the-qa-manual) starts one per module. In **Runs** each sits
under the step that started it, with its own log, cost and model. Its changes land with its
parent's, and stopping the parent stops it.

## Which runtime each agent runs on

Every run belongs to one agent, and each agent names a **runtime**: the coding tool, provider,
endpoint, key, model, reasoning level and any extra arguments it runs with. So planning can think
on a stronger model than the builder writes with.

Pick an agent's runtime on its page under **Configuration → Workflows** or **Configuration →
Board**. **Configuration → Runtimes** lists them, with a **Test** that says whether each one
answers. The first row, **Global default**, is what an agent naming no runtime runs. Planning
runs on the runtime of the **Planning helper** — the agent you talk to in **New idea** and
**Discuss**.

```bash
akb agent                                    # every runtime, then every agent and the row it runs
akb agent runtime add "My gateway" claude-code
akb agent set --runtime my_gateway baseUrl https://my-gateway.example.com
akb agent bind builder my_gateway            # give one agent a runtime of its own
```

Runtimes and API keys are yours alone: git does not carry them and a Cloud workspace does not
share them.
