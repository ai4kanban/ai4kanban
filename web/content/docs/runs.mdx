Everything in [the daily loop](/docs/daily-loop) is a card. The rest of what the board app's
buttons do can be asked for just as plainly, and your agent runs the matching command — the
runs panel and `akb run` are the same list either way.

| You say | What happens |
| --- | --- |
| "what's running?" | the runs going now, and what ran lately |
| "show me that run's log" | its log, or `--follow` to watch it go |
| "stop it" | the run ends and the card comes back |
| "that run died — carry on" | it resumes the agent's own session, counted as a fresh run |
| "use Codex instead" / "switch to Opus" | the board's agent, model, reasoning effort |
| "check my setup works" | one small message through the setup, so a bad login turns up here rather than on your next card |
| "save my API key" | it hands **you** the command to type yourself |

A key is the one thing your agent hands back instead of running: a key it types lands in its
transcript and in your shell history, and the board never reads a saved key back.

When an ask can't run, the answer names the one line that fixes it — `akb install` for a project
with no board, `npm install -g ai4kanban@latest` for an `akb` that is behind, `akb agent test` for
an agent that isn't installed, `akb agent` for a key or provider that isn't set.

## Which tool each agent runs on

Every run belongs to one agent: a flow is run by the role that owns it — planner, builder,
reviewer, or writer on a marketing board — and a spec run by the specialist it names. Each of
them picks the coding tool it runs, so the planner can think on a stronger model than the builder
writes with.

```bash
akb agent                              # every agent, what it runs, and the model under it
akb agent use claude-code              # the board's default — what an agent that picked none runs
akb agent bind builder codex           # give one agent a tool of its own
akb agent set --agent builder model gpt-5.1-codex
```

The pick travels with the repository, in `docs/kanban/ui.config.json`, so every checkout runs each
agent on the same tool. The **model** does not: it is saved in `docs/kanban/.local.json`, which git
does not carry, because a model id is worth nothing on a machine whose CLI never logged into that
provider. Clone the repo somewhere else and each agent keeps its tool and picks its own model
there.

**Configuration → Agents** is the same thing on screen: open an agent and its runtime row sits
above the box that trains it. **Configuration → Runtime** is the tools themselves — one row per
coding agent, opening onto how to reach that one and a **Test** that says whether it answers.

Which tool to put behind an agent — what each of the eight reports back, what a run may touch,
and the settings each takes — is [What each coding agent can do](/docs/connectors).
