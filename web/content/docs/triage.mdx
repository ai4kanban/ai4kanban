**Triage** sits above **Archive** in the rail, with a count. The page groups what the board
holds by the source it came from — Reddit, X, 小红书 — with the source's mark and name on the
group's heading and three light cards to a row under it. A card shows its title and up to
three of the values its source sent with it; click it for the whole thing, the original, and
**Ignore**.

Two tabs: **Waiting**, and **Ignored** for the last 30 days. Search covers everything in the
tab — titles, bodies, sources, those values, and on **Ignored** the reason it was ignored —
including folded groups and the part of a group still behind **More**. The source picker
narrows to one source and combines with the search.

Free to invited Cloud accounts on an Engineering board while it is a preview. On a Marketing
board, and on an account that is signed out or not yet invited, there is no rail row and both
`akb triage fetch` and `akb triage run` refuse.

## A triage item is not a card

Triage is deliberately outside `todo/`. An item is never scheduled, never ranked and never
counted in your board numbers — it is somebody else's sentence, waiting for a decision about
whether there is work in it. Cards are what has been decided. Who decides is yours to pick:
you, by reading the list, or the **Triage** agent, which judges each item and cards what
survives. It is off until you switch it on.

That means triage needs looking at, the way a mailbox does. Ignoring an item takes it out of
**Waiting** for good: its file moves to `docs/kanban/triage/dismissed/`, and no later pull
brings it back. There is no undo, and that is the point — a list you can never empty is one
you stop opening. The **Ignored** tab is a record of the last 30 days of that, read only —
open one to read it in full, and create a card by hand if it turns out to matter after all.

## Sort it

```bash
akb triage run
```

One run judges every item waiting, one at a time. What survives becomes a card; everything
else moves to `dismissed/` with the reason. This command works whether or not the switch
below is on.

Each item is judged twice over: first for duplicates — already supported, already covered by
an open card, or turned down before — then for whether it would actually improve the product.
An item that lands on work a card already owns is ignored rather than merged into that card.

A survivor is created with a refine already scheduled on it, and the board starts those
itself, one per tick. So a run leaves you cards that go on sharpening themselves — it does
not start a build, answer a question, or touch a card that was already there.

The run reports what it did: how many it judged, each new card by id, and how many it
ignored. `akb triage run -f` follows it as it goes.

Only one sort runs at a time. Ignoring an item on the page while a sort is going is safe:
whichever lands first wins, and the other side skips that item.

### Let it sort by itself

**Configuration → Agents → Triage** carries the switch. Off by default, and it asks once
before it goes on, because what it turns on is the board judging an item before you have
seen it:

> **From now on a new item is judged before you see it.** The ones worth doing become cards
> by themselves, each costing one more refine run.

With it on, every batch of new items starts one sort — a pull, **Add** on the page, and
`akb triage add` alike, so an item the **Proposer** writes is judged like any other. A pull
that brought nothing new starts nothing.

A sort reads the list once, when it starts, so anything that arrives while it goes is unseen.
Its close starts the next one for exactly that, and the one after that, until nothing is
waiting. Three things stop the chain, and each waits for the next batch of items or for
`akb triage run`:

- **A sort that judged nothing.** One item no sort can get through would otherwise start
  sorts forever.
- **A sort that failed or was stopped.** Neither is a judgement; the items stay where they are.
- **The switch going off, or Triage closing.** Both are read again each time a sort would
  start. A sort already going finishes.

Switching it on does not sweep what is already waiting — a setting change is not a reason to
spend a backlog's worth of runs. Those items go with the next batch, or with a
`akb triage run` you type.

Running it alongside **Gater** and **Decider** is not recommended, and the board does not stop
you: with all three on, an item from outside can go from Triage to built without one human
confirmation. See [Agents](/docs/agents).

### What a card it wrote says

A card made from an item ends with `## Source`: the item's source id and the path it moved
to under `archived/`, its source type and the values its `meta:` carried, and the original
link. That is how you get from a card back to the sentence somebody wrote.

`archived/` means **a card was made of it** — not that the work is done. The card's own
status says that.

If a run is interrupted between writing a card and recording the item, nothing is lost and
nothing is doubled: the next run reads the source ids off open cards' `## Source` first and
archives anything already accounted for before it judges a thing.

## Where triage keeps things

```
docs/kanban/triage/
├── <item>.md      waiting to be sorted — this is what Triage lists
├── archived/      a card was made of it: `card_id`, `archived_at`
├── dismissed/     ignored: `dismissed_at`, `dismissed_by`, `dismissed_reason`
└── files/         the bytes of anything dropped in, shared by all three
```

Leaving the list is a move, never a delete — the file itself is the record. `dismissed/` is
kept for good and never pruned: the **Ignored** tab draws the last 30 days of it, and *all* of
it holds a later pull off. A dropped file's copy stays in `files/` when the item moves, so the
path written into the item's body is good for as long as the item is.

Ask where one thing already is:

```bash
akb triage check t3_1abcdef
```

It answers `pending`, `archived`, `dismissed` or `unseen`, with the file that says so — the
same rule all three ways in read. A pull is held off by all three; adding by hand only by the
first two, so pasting a link back in is the way out of an accidental ignore. It costs one
extra file: the `dismissed/` record stays where it is, and the item waits again beside it.

A board written before this moves itself the first time triage is read: items come up out of
`triage/inbox/`, its dropped files into `triage/files/`, and every `handled.md` id with no file
left becomes a `dismissed/` record carrying the id and the time and nothing else — the words
were never kept, and the page says so rather than inventing them. Nothing is overwritten, and a
migration cut short carries on the next time.

## Connect a source

Two settings, both filled in by hand for now.

**The endpoint** goes in your board's `docs/kanban/config.md`, as one more line beside the
settings already there:

```markdown
- **Triage endpoint** — https://signals.example.com/v1/pull
```

**The token** goes in `docs/kanban/.env`, where the board keeps every key. It is never shown
on a screen, written to a log, or repeated in an error:

```
TRIAGE_ENDPOINT_TOKEN=…
```

`docs/kanban/.env` is kept out of git by the board's own `.gitignore`.

These replaced the earlier `Signal endpoint` and `SIGNAL_ENDPOINT_TOKEN`, which are no longer
read, and the `akb signals` command, which is gone. Rename them in your own `config.md` and
`.env`, and update any script or recurring card that still runs the old command — nothing is
rewritten for you.

## What the endpoint returns

The board sends `GET <your endpoint>` with `Authorization: Bearer <your token>` and expects
JSON shaped like this:

```json
{
  "signals": [
    {
      "title": "Three of us run Claude Code and the conventions keep getting reverted",
      "summary": "We each have Claude Code open on the same repo…",
      "source_type": "reddit",
      "meta": { "subreddit": "r/ClaudeAI", "author": "u/mira", "score": "312 upvotes" },
      "url": "https://www.reddit.com/r/ClaudeAI/comments/1abcdef/",
      "collected_at": "2026-09-06T21:40:00Z",
      "source_id": "t3_1abcdef"
    }
  ]
}
```

Only **`title`** and **`summary`** are required, and a signal missing either is not imported —
the pull counts it as a failure and names what was missing. Everything else is optional.

- **`source_type`** is one key off the board's source list. It ships with `reddit`, `x`,
  `xiaohongshu`, `weibo`, `zhihu` and `youtube`; a key that is not on it is kept exactly as
  you sent it and drawn as itself, with no mark. Leave it out and the board reads the link's
  domain against the same list — and if that matches nothing, the item simply has no source.
  Nothing is invented from a domain or a file name.
- **`meta`** is free key-value pairs — `subreddit`, `author`, whatever your source has. The
  board does not validate, translate or fill them in, and takes only values a single line
  holds; objects and lists are left out. The page draws the values, never the keys, so write
  values that read on their own.
- **`url`** is the thing itself, opened by **Open**. **`collected_at`** is when the data
  platform collected the post, not when your board pulled it; the board records the import
  time itself.
- **`source_id`** is the signal's identity. The board dedupes on it, against everything
  waiting, everything made into a card, everything ever ignored, and the rest of the same
  batch — so the same post sent on ten pulls is one file. Left out, it is derived from the
  link or the words.
- There is no paging and no ceiling. What the endpoint sends is what the board takes.

An endpoint written before the source list may still send **`platform`** or **`source`** as
free text. Both are read through the same list: a match is that source, and anything else is
kept as a `meta` entry under `source` rather than guessed at. Files already in triage are read
the same way, and are not rewritten.

Turning what a platform actually returns into this shape is yours to write — that converter is
the reason the board never has to know a platform. Writing the endpoint rather than pointing at
one? [The triage endpoint contract](/docs/triage-endpoint) is the whole of what it has to keep.

## Pull

```bash
akb triage fetch
```

It reports what it did — `Added 12 items, skipped 3, failed 1.` — and explains each failure
on its own line. A request that fails, an answer it cannot read, and a setting still to be
filled in all write nothing at all: triage is left exactly as it was.

The first successful pull makes `docs/kanban/triage/` and seeds a recurring card,
**Fetch triage items**, in `todo/recurring/`. Give that card a cadence and the board pulls on
its own; leave it without one and nothing runs until you ask. Delete the card if you don't want
the job — nothing puts it back.

## Put something in yourself

The endpoint is not the only way in. **Add** in the toolbar opens a small box under the
button: paste a link, write it out, or attach a file — one box for all three, and a note
typed alongside a file goes in with it. A file dropped anywhere on the page is held there by
name until you press **Add**; nothing is written before that, and closing the box keeps the
draft. `⌘/Ctrl + Enter` adds it, plain Enter is a new line.

A pasted link's domain is read against the source list. A match is that source; anything else
keeps the domain as a `meta` entry under `domain`. A file keeps its name under `filename`, and
neither is given a source.

From a terminal:

```bash
akb triage add --title "What it is" --text "Its own words." --source "where it came from"
```

`--source` goes through the same list — `小红书` is `xiaohongshu`, and anything the list has
not got is kept as a `meta` entry under `source`. `--file <path>` takes the body from a file
when it is longer than a line or two. Neither needs an endpoint or a Cloud account. An item
already waiting, or already made into a card, is refused and told where it is; one only
ignored is taken.

This is also where the board's own **Proposer** writes: with it switched on, every card you
archive is reflected on and what should follow it lands here, carrying the card that prompted
it. See [Agents](/docs/agents). With **Triage** on as well, what it proposes is sorted
without being read — the board's own follow-ups become cards the same way an outside item
does.
