Claude Code already has subagents, agent view, agent teams, task lists, and Git worktrees. Those tools coordinate coding sessions. They do not decide which requests are ready to build, which tasks depend on one another, which product decisions every task should follow, or which finished change should land first.

AI4Kanban adds a repository-local Kanban board for those project-level decisions. It turns rough requests into task cards, stores shared product memory in Markdown, starts Claude Code runs, and manages review and landing.

## Claude Code coordinates agents. AI4Kanban coordinates the project.

[Claude Code can parallelize work with subagents, agent view, agent teams, worktrees, and batch operations](https://code.claude.com/docs/en/agents). Each coordinates execution in a different way. AI4Kanban coordinates the requirements, dependencies, and decisions that those runs receive.

| Claude Code tool | What it coordinates | What AI4Kanban adds |
| --- | --- | --- |
| Subagents | Bounded work delegated by one session | A reviewed requirement for the work they receive |
| Agent teams and their task list | Work claimed by the current team | A Git-tracked backlog of current, blocked, future, and recurring tasks |
| Agent view | Claude Code sessions that are running now | Readiness, dependencies, product questions, and delivery status for the whole project |
| Worktrees | File edits made by concurrent sessions | Dependency scheduling, review, landing order, and conflict resolution |
| Conversation context and auto memory | Claude's working context and notes | Curated product decisions shared with every relevant task |

Each card on the AI4Kanban board stores 1 task's outcome, constraints, dependencies, open product questions, and verification criteria. Independent cards can build together; blocked cards wait; reviewed deliveries land one at a time.

## Can AI4Kanban prepare a Claude Code task before coding?

Yes. AI4Kanban calls this step refinement: it uses Claude Code to turn a rough request into a build-ready requirement before any code is edited. Claude Code reads the repository, project goal, related tasks, and previous product decisions first.

| Before Claude Code starts coding | What Claude Code does for AI4Kanban |
| --- | --- |
| Check the request | Define its outcome, scope, defaults, acceptance criteria, dependencies, and edge cases |
| Resolve a factual uncertainty | Inspect the code and choose a safe answer from project evidence |
| Find a consequential product choice | Add concrete options and a recommendation for you |
| Find that the request is too large for 1 task | Split it into subtasks and record their dependencies |

The implementation session then receives the approved requirement instead of reconstructing intent from a rough prompt.

## How does AI4Kanban share project memory across tasks?

AI4Kanban stores task state and shared product memory outside Claude Code's chat. Every task can reuse the decisions that apply to it, even after compaction, `/clear`, or a new session. Task requirements, open questions, dependencies, verification criteria, and delivery history also remain on the board.

Project memory is not a saved transcript. AI4Kanban keeps a fixed set of 4 small Markdown files for the whole project and another set for each module.

| File | What future tasks learn from it |
| --- | --- |
| `readme.md` | User-facing behavior already shipped |
| `decisions.md` | Product decisions that still apply |
| `rejected.md` | Ideas that should not be proposed again |
| `redesign.md` | Design mistakes future work should avoid |

Each card names the parts of the product it changes, such as the site, local app, or API. The task loads project memory plus the memory for those modules. Claude Code gets the decisions it needs without loading every card or replaying old conversations.

Claude Code's own [`CLAUDE.md` and auto memory](https://code.claude.com/docs/en/claude-directory) still apply. Use them for coding conventions and Claude's working notes. AI4Kanban memory keeps the product decisions that future tasks for the same part of the project should follow.

Read [why project decisions become the bottleneck](/blog/project-decisions-are-the-bottleneck).

## Which decisions does AI4Kanban leave to me?

AI4Kanban leaves only product decisions that Claude Code cannot safely settle from repository evidence.

**Routine questions:** Claude Code researches them, chooses a safe answer, and updates the requirement.

**Product decisions:** AI4Kanban waits when the answer changes behavior, scope, privacy, compatibility, risk, or ongoing cost. You receive concrete options, trade-offs, and a recommendation.

When task preparation is complete, the card still waits for you to click **Implement**. After a fresh Claude Code session reviews the implementation, landing is automatic unless you enable diff approval for a second checkpoint. AI4Kanban never pushes.

## How do I know when Claude Code needs me?

Questions and review requests appear in the app and can be sent to Slack. Running and Landed are status only. A failed run keeps its task, worktree, and Claude Code session so you can inspect or resume it. Other tasks keep moving while 1 waits for you.

## Can I keep my existing Claude Code setup?

Yes. AI4Kanban launches your installed Claude Code CLI and keeps its login, `CLAUDE.md`, rules, skills, hooks, MCP servers, permissions, and project commands. Denied tool calls remain visible in the run log.

[Claude Code loads each extension at a different point in its context](https://code.claude.com/docs/en/features-overview). AI4Kanban invokes its `/kanban` skill directly, then supplies the current task and only the project and module memory it needs.

Choose a Claude subscription, an Anthropic API key, or an Anthropic-compatible endpoint. Named runtimes can use different models and reasoning effort for task preparation, implementation, review, and specialist work. Empty fields keep Claude Code's defaults.

## How does AI4Kanban handle parallel Claude Code changes?

When automatic Git commits are enabled, each task gets its own delivery branch and Git worktree. Dependencies stop blocked tasks from starting too early, while independent tasks can build together.

Worktrees stop concurrent sessions from overwriting each other's files while they run. Two branches can still change the same lines or make behavior that no longer works when both changes are combined. AI4Kanban therefore lands reviewed deliveries one at a time. If the target branch moved, it rebases the next delivery and reviews the result again. If Git reports a conflict, Claude Code resolves the conflicting files and a fresh review checks the combined change before it lands.

<FAQ title="Frequently asked questions">

<FAQItem question="Does AI4Kanban use my Claude subscription, or do I need an Anthropic API key?">

Both work. Use the login already held by your Claude CLI, an Anthropic API key, or an Anthropic-compatible gateway. The selected provider is explicit, so a saved API key does not silently replace a subscription run.

</FAQItem>

<FAQItem question="Can I choose the Claude model used for planning, implementation, review, and testing?">

Yes. Create named Claude Code runtimes with their own model and reasoning effort, then assign them to AI4Kanban workflows. Tests run during implementation and review rather than in a separate testing stage. Empty settings keep Claude Code's defaults.

</FAQItem>

<FAQItem question="Does AI4Kanban require an MCP server?">

No. The local app invokes Claude Code and its `/kanban` skill directly. Your existing MCP servers remain available to Claude when a task needs them.

</FAQItem>

<FAQItem question="How much context does AI4Kanban add to a Claude Code run?">

There is no fixed token number because task and memory size vary. Each run receives its task, instructions for the current step, project memory, and memory for the modules that task changes. It does not load every card or replay AI4Kanban's chat history.

</FAQItem>

<FAQItem question="Can Claude Code update the AI4Kanban board itself?">

Yes. The AI4Kanban skill gives Claude Code structured commands for creating and preparing cards, splitting large tasks into subtasks, recording dependencies, answering questions, and updating task status.

</FAQItem>

<FAQItem question="Can an AI4Kanban task use Claude Code subagents or agent teams?">

Yes, when your Claude Code configuration and permissions allow them. The AI4Kanban card still records 1 approved requirement, 1 delivery branch and worktree, 1 review, and 1 final status for the whole run. [Claude Code agent teams have their own shared task list](https://code.claude.com/docs/en/agent-teams) for coordinating their workers inside that run.

</FAQItem>

<FAQItem question="What is the difference between an AI4Kanban task, a Claude Code session, and Claude Code's task list?">

An AI4Kanban task stores a requirement, dependencies, questions, verification criteria, and delivery status in the repository. A Claude Code session performs 1 step such as task preparation, implementation, review, or correction. Claude Code's task list coordinates workers inside an active agent team. Several sessions can contribute to 1 AI4Kanban task, and the task remains after those sessions end.

</FAQItem>

<FAQItem question="Can I resume the same Claude Code session from an AI4Kanban card?">

Yes. A failed run keeps its Claude Code session ID, worktree, and code changes. Resume continues that conversation with the task state intact instead of starting over.

</FAQItem>

<FAQItem question="What happens if Claude reaches a usage limit or stops halfway through?">

AI4Kanban ends a rate-limited Claude Code run instead of waiting through Claude Code's long retry cycle. The task, code changes, worktree, and resumable session remain available, and other tasks can continue. A configurable silence timeout handles runs that stop producing output.

</FAQItem>

<FAQItem question="Can Claude work in my main checkout instead of an isolated worktree?">

Yes. Disable automatic Git commits globally or for 1 task run. Claude Code then works in the current checkout and you handle the commit after review.

</FAQItem>

<FAQItem question="How are .env files, dependencies, databases, Docker resources, and ports handled in worktrees?">

A worktree created by AI4Kanban begins with tracked files. Add a project implementation rule that tells Claude Code how to install dependencies and prepare local configuration. Ignored files are not copied automatically. Ports, databases, and Docker names are still shared by worktrees, so parallel tasks need distinct values when the project requires them. Agent credentials stay in the ignored `docs/kanban/.env` file.

</FAQItem>

<FAQItem question="What if parallel tasks invalidate each other's assumptions or conflict when they land?">

Dependencies make tasks that must land in order wait for one another. If another task changes the target branch, AI4Kanban rebases the next reviewed change onto that new version. A clean rebase is reviewed again. A Git conflict gets a focused Claude Code resolution run, followed by another review before landing.

</FAQItem>

<FAQItem question="Who runs tests and decides that a task is done?">

The implementation run follows the task's verification criteria. A fresh Claude Code session then checks the approved requirement and diff, fixes plain mistakes, and reruns focused tests. The approved requirement defines done; tests provide evidence that the implementation meets it. Enable diff approval when you want to inspect the final change yourself.

</FAQItem>

<FAQItem question="Will Claude commit, merge, push, or delete a worktree without my approval?">

Clicking **Implement** authorizes automatic commits, 1 reviewed squash commit on the target branch, and cleanup of the delivery branch and worktree after landing. Enable diff approval for a second checkpoint, or disable automatic Git commits to manage Git yourself. AI4Kanban never pushes.

</FAQItem>

<FAQItem question="Can I use the same AI4Kanban board with another coding agent later?">

Yes. AI4Kanban cards, dependencies, requirements, and project memory are agent-independent. Pick Codex, Cursor, OpenCode, or another supported runtime for new work. An existing resumable conversation remains tied to the coding agent that created it.

</FAQItem>

</FAQ>
