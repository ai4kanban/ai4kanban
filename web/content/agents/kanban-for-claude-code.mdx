WildCrane brings coding and marketing workflows into one agent workspace for indie hackers. Built-in specialists draft the parts that need your judgment before Claude Code carries the work forward.

Catch a wrong layout or message while it is still a draft, then let Claude Code complete the agreed work. You review the key details without managing every step, and independent tasks can move forward in parallel.

## What can I review before Claude Code builds?

While planning a task, WildCrane brings in the specialists its changes call for. They prepare drafts for the parts that need your judgment:

- **Interface**: Layouts, interactions and screen text in desktop and phone previews.
- **Prompts**: Exact changes to prompts, skills and agent instructions, shown as diffs.
- **Copy**: The wording for a landing page, release note or user guide.
- **Emails**: Subject, body copy, and desktop and phone previews.

Preview interface drafts on the task card without building your whole project. Check the layout and interactions, change what is wrong, or drop an idea before there is an implementation to undo. The approved drafts give Claude Code concrete requirements for the parts you care about, so it can build within the agreed scope instead of filling in those details itself.

Some work needs more than one stage, such as copy approval before screen design. Review each required stage before the next starts. Small fixes can go straight to implementation when there is no draft or product decision you need to review.

The [coding workflow](/workflows/coding) uses these drafts to settle key details before implementation. A feature and its launch-page copy can share the same board and project context, with each task getting the drafts it needs. See how [SaaS founders combine product development and marketing](/solutions/saas).

## How is WildCrane different from Claude Code's task lists?

[Claude Code's task list](https://code.claude.com/docs/en/interactive-mode#task-list) is a checklist Claude uses to organize multi-step work. Tasks can survive context compaction, and a named list can be shared across sessions. [Agent teams](https://code.claude.com/docs/en/agent-teams#assign-and-claim-tasks) also use shared lists to assign work and track dependencies.

WildCrane adds the workflow around each task: discuss an idea, review the key drafts, answer open questions, build, and see what was delivered. Coding and marketing tasks share one board, with a runtime chosen for each agent. After delivery, follow-up suggestions and scheduled QA help find work the original task left behind.

## How does WildCrane prepare Claude Code before coding?

WildCrane uses Claude Code to refine a rough request into a build-ready task. Refinement happens before implementation: Claude reads the repository, product description, related tasks, and previous product decisions, then writes the missing detail onto the card.

Claude Code is expected to settle factual questions itself. It inspects the code, checks existing behavior, and chooses a safe answer when the repository provides one. WildCrane stops only when the remaining choice changes product behavior, scope, privacy, compatibility, risk, or ongoing cost.

The finished card contains the outcome, boundaries, dependencies, edge cases, and verification criteria that the implementation run must follow. If the work is too large, Claude splits it into smaller cards and records the order in which they can run.

## What project context survives between Claude Code sessions?

**Each card** keeps the requirements, approved drafts, open questions, dependencies, progress and delivery result for one task. These stay with the task when you start a new Claude Code session.

**[Project memory](/docs/memory)** carries relevant preferences and decisions into later tasks. Specialists keep the preferences and decisions relevant to their work: a correction to landing-page copy can guide the next copy draft, while an agreed product behavior can guide later development.

The card tells agents what this task must deliver. Memory helps them follow what you have already settled when they work on the next task.

[Claude Code's own instructions and memory](https://code.claude.com/docs/en/memory) still apply alongside WildCrane's project memory.

## Can I use Codex for writing and Claude Code for coding?

Yes. Use Codex for copywriting and Claude Code for implementation, with both working from the same board and relevant project context. The approved copy stays on the card for Claude Code to follow when building the page.

You can also choose Cursor, OpenCode or another supported runtime. The tools run on your machine with your own subscriptions or keys.

## How do Claude Code subagents and agent teams fit?

They run inside an WildCrane task. The card remains the outer unit that defines the outcome, branch, worktree, and final status. Claude Code can divide the implementation among subagents or an agent team when its configuration and permissions allow them.

Claude Code's team task list coordinates workers inside that run. The WildCrane board coordinates the project across runs: a later card can depend on this card, reuse the decision it produced, or wait until its change has landed.

[Claude Code stores agent-team configuration and task lists under the user's Claude directory](https://code.claude.com/docs/en/agent-teams). WildCrane does not copy that runtime state into the repository. It records the product requirement and delivery result that must outlive the team.

## Does WildCrane replace my Claude Code configuration?

No. WildCrane launches the Claude Code CLI already installed on your machine. Your login, `CLAUDE.md`, rules, skills, hooks, MCP servers, permissions, and project commands remain in effect.

[Claude Code loads those extensions at different points in a session](https://code.claude.com/docs/en/features-overview). WildCrane invokes its `/kanban` skill directly and adds the current card plus the relevant project memory. It does not require an MCP server of its own.

Choose the login already used by your Claude CLI, an Anthropic API key, or an Anthropic-compatible endpoint for Claude Code.

## Can a failed card resume the same Claude Code session?

Yes. WildCrane assigns the Claude Code session ID before a run starts, so even a run that fails in its first seconds can be resumed from the same card. The card keeps its worktree and code changes; Resume continues the existing Claude conversation instead of rebuilding its context from the beginning.

WildCrane also makes Claude Code stop immediately when the provider returns a rate limit. Claude Code would normally retry for longer, but a background card should not occupy a run slot while no progress is possible. The failed card remains resumable, and other tasks can continue.

A separate silence timeout ends a run that stops producing output. You choose the timeout in Configuration, and 0 disables it.

## Can WildCrane supervise several Claude Code tasks at once?

Yes. Claude Code agent view shows the sessions themselves. WildCrane decides which project tasks may start, based on card readiness and dependencies.

When automatic Git commits are enabled, each task gets its own branch and worktree. Independent tasks can run together; dependent tasks wait. Finished changes land on the target branch one at a time. If another task changed that branch, WildCrane rebases the next change onto it and lands it — and keeps retrying, without asking you, for as long as the branch keeps moving. A Git conflict gets a focused Claude Code resolution run before landing.

Worktrees prevent concurrent sessions from overwriting the same checkout. The landing process handles the separate problem of 2 branches changing the same lines or producing behavior that no longer works when combined.

## When does a task need my input?

A task waits for you when a product choice needs your judgment or a draft needs approval. Open the card to answer the question, approve the draft, or request changes. Other independent tasks can continue.

Approving a draft updates the plan. Once the required drafts and questions are settled, click **Build** to start implementation. If a new decision needs your attention during the work, answer it on the card. After delivery, compare the result with the approved drafts and try the changed behavior.

Notifications in the app alert you when a task needs an answer or a draft is ready for review. Connect Slack to receive these notifications there too. Each notification links to the card where you can review the draft or answer the question.

## Find follow-up work after delivery

WildCrane can suggest follow-up work based on the completed card and what actually shipped. Suggestions point out gaps or useful next steps, with a link to the work they came from.

They arrive in [Triage](/docs/triage), where you can discuss an item, make it a card, or ignore it. You can also enable automatic sorting to turn worthwhile suggestions into planned cards.

## Catch regressions with scheduled QA

The Coding workflow includes a scheduled **QA manager**. It follows finished cards, updates the test cases their changes affect, and runs the steps against the product. Each step has evidence such as a screenshot, GIF or log; a step it cannot verify says why.

It also adds coverage for existing parts of the product. Read the cases in **Test cases** on the board. Failures go to Triage with the case and step, so you can turn them into work. You choose how often QA runs or disable it. See [test cases and scheduled QA](/docs/daily-loop#test-cases).

<FAQ title="Frequently asked questions">

<FAQItem question="Does WildCrane use my Claude subscription, or do I need an Anthropic API key?">

Both work. Use the login already held by your Claude CLI, an Anthropic API key, or an Anthropic-compatible gateway. The selected provider is explicit, so a saved API key does not silently replace a subscription run.

</FAQItem>

<FAQItem question="Can I choose the Claude model for different kinds of work?">

Yes. Set the model and reasoning effort on each agent's page in Configuration. Planning and implementation can use different Claude models; leave the model empty to use Claude Code's default. You can also assign an agent a different runtime, such as Codex, Cursor or OpenCode. See [multi-runtime support](/docs/connectors).

</FAQItem>

<FAQItem question="How much context does WildCrane add to a Claude Code run?">

There is no fixed token number because task and memory size vary. Each run receives the current card, instructions for the current step, and the project memory a planning decision could come from. It does not load the whole board or replay WildCrane's chat history.

</FAQItem>

<FAQItem question="Can Claude Code update the WildCrane board itself?">

Yes. The `/kanban` skill gives Claude Code commands for creating and preparing cards, splitting large tasks into subtasks, recording dependencies, answering questions, and updating task status.

</FAQItem>

<FAQItem question="Can Claude Code work in my main checkout instead of a worktree?">

Yes. Disable automatic Git commits globally or for 1 task run. Claude Code then works in the current checkout and you handle the commit after review.

</FAQItem>

<FAQItem question="How are .env files, dependencies, databases, Docker resources, and ports handled in worktrees?">

A worktree created by WildCrane begins with tracked files. Add an implementation rule that tells Claude Code how to install dependencies and prepare local configuration. Ignored files are not copied automatically. Ports, databases, and Docker names are still shared by worktrees, so parallel tasks need distinct values when the project requires them. Agent credentials stay in the ignored `docs/kanban/.env` file.

</FAQItem>

<FAQItem question="Who runs tests and decides that a task is done?">

The implementation agent runs the checks required by the card. The approved requirements and drafts define what it must deliver, and your project's checks gate landing. After cards finish, the scheduled QA manager maintains and runs user-facing test cases as the product changes. Its findings go to Triage for follow-up work.

</FAQItem>

<FAQItem question="Will Claude Code commit, merge, push, or delete a worktree without my approval?">

Clicking **Build** authorizes automatic commits, one squash commit on the target branch, and cleanup of the delivery branch and worktree after landing. Disable automatic Git commits to manage Git yourself. WildCrane never pushes.

</FAQItem>

<FAQItem question="Can I use the same WildCrane board with another coding agent later?">

Yes. WildCrane cards, dependencies, requirements, and project memory are agent-independent. Pick Codex, Cursor, OpenCode, or another supported coding agent for new work — for the whole board, or for one agent on it. A resumable Claude Code conversation remains tied to Claude Code.

</FAQItem>

</FAQ>
