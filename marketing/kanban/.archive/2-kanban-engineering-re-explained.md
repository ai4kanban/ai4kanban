Imported, already published. A 小红书 post that re-explains the coined term "Kanban
Engineering": the bottleneck in software is the requirement end, because bugs, docs, tests
and code all take their context from the repository while a requirement only exists in
someone's head — and anything a person has to produce becomes the bottleneck. It then names
the four problems an AI has to solve before that changes — clarifying a feature, proposing
work, planning a release, and turning outside input into requirements — each with the metric
it would be measured by, and closes on AI4Kanban 0.5.0 shipping.
