**Angle — still to pick.** (a) *Approve a screen, not a paragraph*: open on a card carrying a
working UI mockup, so the taste call is made by looking — needs a real mockup screenshot
before it can be written. (b) *The technology choice is a card, not a chat*: open on the
comparison spec agent settling a library pick with its tradeoffs on the card — narrower, and
less to show. (c) *Write your own spec agent*: open on the agent folder a project adds itself
— only lands with people already running the board, so it is retention, not reach.

**Channels — still to pick.** 小红书 leads and X follows (a screenshot-led piece is what that

**Who it is for.** Developers who have had an agent build the wrong screen from a paragraph
they approved.

**Blocked on one thing.** Capture the mockup screenshot the piece is built around first. A
piece about this without the screenshot is not worth publishing.

**What it must say.** Lead with the artifact — a real mockup from a real card. Name the second
agent too: `technology-selection` puts the library choice and its tradeoffs on the card, so the
pattern reads as general rather than as one UI feature. Close on the extension point — a
project writes its own agent as a folder with an `AGENT.md`. One sentence, not a tutorial.

**What it may not claim.** That the mockup is production UI, or that the board designs for
you: it settles a decision early, and a person still makes it. This is about deciding earlier,
not about generating visuals.
