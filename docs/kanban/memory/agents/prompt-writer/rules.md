# Rules

## skill

- **skill 和工作流的 description 写触发条件加一句它做什么**（全项目）：以「Use when…」开头，不写成给用户看的流程介绍（如「Approve the slides…」）；不列产出或功能清单，但不能只剩触发条件。界面上给用户看的说明另算。
- **提示词只写这个 agent 要做的事**（全项目）：不写何时运行、多久一次（调度归看板程序和界面），不写别的流程读什么；启动提示只留身份、看板路径这类变量，不加看不出必要的禁令。
- **guide 与 AGENT.md 分层**（全项目）：guide 是核心层，只放看板机制（如 `multi-stage-drafting`）；agent 自己领域的指令，哪怕几个 agent 都用，也各写在自己目录里，绝不写进 guide；所有领头 Agent 共有的前提（如「卡片就是方案」）写进它们共用的提示词或默认成立，不写进某一个的 `AGENT.md`。
- **随 akb 发出的指南不引用本仓库文件**（全项目）：`cli/src/guide/*.md` 和内置 `AGENT.md` 在用户项目里运行，不能指向 `kanban-ui/design.md` 这类只在本仓库存在的文件，要的标准直接写成通用描述。
- **一个 agent 只有一份 `AGENT.md`**（全项目）：流程写到最精简，不另拆 `process.md`；只在特定条件下才用的细节放同目录的附属文件（如 `template-selection.md`），由 `AGENT.md` 写明何时读，agent 自己按需读取；简介、中英文显示名按内置 agent 的写法对齐。
- **选 agent 的规则写进简介**（全项目）：规划只读各 agent 的简介，何时请它、请完接谁都写在简介里；类型和用处只举例不穷举，只写同一工作流内的边界（如插图 vs 界面稿）；阶段、产出等流程细节编排用不上，不进简介。
- **分阶段的流程按 stage 写**（全项目）：写成 Stage 1 … / Stage 2 …，每段写明产出；阶段推进靠看板的批准，领头 agent 不在阶段末尾提确认问题；不写 agent 排在第几阶段，只说产出是中间稿还是最终稿，也不加解释顺序的句子。
- **判断标准不用「小/大」**（全项目）：换成可判断的条件（如「从零写或从零重写」「措辞是否还要用户定」）；agent 自会判断的话（如 however large）不写；避免「leave it off」这类指代不明的说法。
- **不替 agent 定状态和记忆的管法**（全项目）：写周期 agent 时问用户两遍之间的状态怎么存，写进它的规则；不预设 `run-state.md` 这类文件。
- **通用说明不夹带本看板偏好**（全项目）：内置 agent 只写普适标准、相信 agent 的判断，不列候选类型限定范围；本看板的偏好放「你的要求」或拒绝记录。
- **不限制 agent 怎么做素材**（全项目）：TSX/HTML 仿真界面、代码绘制、真实截图都可以；不强制先去目录里找，卡片指定的就用，其余自己做，现成的可能省事时才查；不写「任何媒介」，让它读 `<Asset>` 支持格式的短 guide（由常量如 `${AKB_ASSET_GUIDE}` 注入）。
- **能力不写成卖点**（全项目）：把「能跑 canvas、WebGL」列成特性，agent 会设法用上；写成默认做法加例外条件。
- **多份上下文要分块**（全项目）：一个提示里带多张卡或多段对话时，每份放进有明确边界的块，并写明不得跨块取用。
- **看板位置写绝对路径**（全项目）：给在构建目录里运行的 agent（构建、冲突、hook）指看板文件时由程序填绝对路径，相对的 `docs/kanban/...` 在那里不存在。
- **不规定 agent 产出的写法**（全项目）：读得懂就行，不规定草稿里的标题层级、不要求附示例输出；变体、多语言怎么做交给 agent，只在常需要多语言的 agent（如 copywriting）里提一句，并给真实的 `<Asset … variants=…>` 代码示例而不是文字描述。
- **不为新会话补操作日志**（全项目）：改了什么已在卡片和产物里，卡片就是事实来源；只有一个 agent 用到的开关不写进写 agent 的通用说明。
- **砍需求就删流程**（全项目）：放宽或删掉一项要求时，删掉支撑它的步骤和报告，不写成旧流程的例外；改完核对提示词确实变短。
- **新做法单起一条**（全项目）：新的独立做法不塞进已有规则把它拉长；例外不放句首；agent 自然会按专门规定办的情况不写。
- **新概念先定义再用**（全项目）：提示词引入的术语（如拍法、内容、道具）先给出可判断的定义，全文统一用这几个词。
- **指记忆文件写具体路径**（全项目）：直接写 `memory/agents/planner/<module>/rejected.md` 这样的路径，不用「流程列在 `rejected` 下的文件」这类绕弯说法。
- **规则只写给真正用它的 agent**（全项目）：用不上的 agent 不带这段指令，同一句不在多个文件里重复。
- **默认值只写一次**（全项目）：取值顺序写成「用户指定 → 平台 → 默认」，其余地方用占位（如 `<w>x<h>`），不到处写死默认值；文件名用简单比例（`3x4`），不用像素尺寸。
- **写完整短句**（全项目）：一句只讲一个要求，不省略主语和宾语，不把几个要求挤进一句。
- **格式要求给一行示例**（全项目）：直接给 agent 照抄的一行（如 `- [x] Output: `./out/email/``），不用括号叠补充规则；只要求检查真正用到的，能一行说清的不要求逐个文件写。
- **不预设用户项目的形态**（全项目）：如不假定有「项目内博客」；去向这类取值按用户指定 → agent rules 里的项目默认 → 记忆 → 推断，都定不了才问。
