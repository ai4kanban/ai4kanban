# Rules

## skill

- **多份上下文要分块**（全项目）：一个提示里带多张卡或多段对话时，每份各放进有明确边界的块（XML 标签或分隔线），并写明不得跨块取用。
- **看板位置写绝对路径**（全项目）：给在构建目录里运行的 agent（构建、冲突、hook）指看板文件时，由程序填入绝对路径；`docs/kanban/...` 这种相对写法在那里不存在。
- **提示词只写这个 agent 要做的事**（全项目）：不写何时运行、多久一次（调度由看板程序和界面决定），也不写别的流程读什么；`board.md` 这类共享守则是给 agent 的手册，不是用户说明。
- **一个 agent 只有一份 `AGENT.md`**（全项目）：流程写到最精简，不另拆 `process.md`；简介、中英文显示名按内置 agent 的写法对齐。
- **不替 agent 定状态和记忆的管法**（全项目）：写周期 agent 时问用户两遍之间的状态怎么存，写进它的规则；不预设 `run-state.md` 这类文件。
- **不为一类 agent 建共享守则**（全项目）：只有某个 agent 用到的指令（如列卡命令、送待筛选）写进它自己的规则；启动提示只留身份、看板路径这类变量，不加看不出必要的禁令。
- **通用说明不夹带本看板偏好**（全项目）：内置 agent 的通用说明只写普适标准、相信 agent 的判断；本看板的偏好放「你的要求」或拒绝记录。
- **标准写成一句判断，不列候选类型**（全项目）：列出的几类读起来像只许这几类，是限制而不是提示。
- **指记忆文件写具体路径**（全项目）：提到某份记忆文件时直接写路径（如 `memory/agents/planner/rejected.md`、`memory/agents/planner/<module>/rejected.md`），不用「流程列在 `rejected` 下的文件」这类绕弯说法。
