# Rules

## skill

- **多份上下文要分块**（全项目）：一个提示里带多张卡或多段对话时，每份各放进有明确边界的块（XML 标签或分隔线），并写明不得跨块取用。
- **看板位置写绝对路径**（全项目）：给在构建目录里运行的 agent（构建、冲突、hook）指看板文件时，由程序填入绝对路径；`docs/kanban/...` 这种相对写法在那里不存在。
- **提示词只写这个 agent 要做的事**（全项目）：不写何时运行、多久一次（调度由看板程序和界面决定），也不写别的流程读什么；akb 的 guide 是核心层，agent 是其上一层，只有某个 agent 用到的指令写进它自己的 `AGENT.md`，绝不写进 guide（要举例就写明是举例）；多个 agent 重复的同一机制抽成共享 guide（如 `multi-stage-drafting`），各 agent 只写自己的那部分；启动提示只留身份、看板路径这类变量，不加看不出必要的禁令。
- **分阶段的流程按 stage 写**（全项目）：用「stage」一词，写成 Stage 1 … / Stage 2 …，每段写明产出和确认点。
- **不写 agent 排在第几阶段**（全项目）：一个 agent 的产出只说是中间稿还是最终稿，排第几由前后的 agent 决定；也不加解释顺序的句子，多一句解释常更乱。
- **判断标准不用「小/大」**（全项目）：「小改动」「大改动」含糊，换成可判断的条件（如「从零写或从零重写」、「措辞是否还要用户定」）；agent 自会判断的话（如 however large）不写；避免「leave it off」这类指代不明的说法。
- **选 agent 的规则写进简介**（全项目）：规划挑 agent 时只读各 agent 的简介、不读 `AGENT.md` 正文，何时请它、请完接谁都写在简介里。
- **一个 agent 只有一份 `AGENT.md`**（全项目）：流程写到最精简，不另拆 `process.md`；简介、中英文显示名按内置 agent 的写法对齐。
- **不替 agent 定状态和记忆的管法**（全项目）：写周期 agent 时问用户两遍之间的状态怎么存，写进它的规则；不预设 `run-state.md` 这类文件。
- **通用说明不夹带本看板偏好**（全项目）：内置 agent 的通用说明只写普适标准、相信 agent 的判断，不列候选类型来限定范围；本看板的偏好放「你的要求」或拒绝记录。
- **agent 描述举例不穷举**（全项目）：类型、用处都只举例，范围靠边界划定；只写同一工作流内的边界（如插图 vs 界面稿），不排除其他工作流的 agent——选 agent 只在本工作流里挑。
- **不限制 agent 怎么做素材**（全项目）：TSX/HTML 仿真界面、代码绘制、真实截图都可以；也不写「任何媒介」，而是让它读一份 `<Asset>` 支持格式的短 guide（由常量如 `${AKB_ASSET_GUIDE}` 注入）。
- **指记忆文件写具体路径**（全项目）：提到某份记忆文件时直接写路径（如 `memory/agents/planner/<module>/rejected.md`），不用「流程列在 `rejected` 下的文件」这类绕弯说法。
