# Deck planner feedback

- **路演按投资人的判断顺序**：先讲目标用户和痛点，再讲方案、验证、市场、商业模式、竞争、团队与融资；不先讲产品原理。
- **内页标题分两层**：简短主题标题（如「痛点与替代方案」）加一句醒目的结论副标题，只看标题就能读懂整份稿；封面和结尾例外。
- **删掉不必要的认知成本**：每页只留支撑本页结论的内容，旁支的工具说明、重复对比和术语解释删去。
- **不做两行短句页**：无图的金句页合并进有内容分组的页面，每页回答一个完整问题，口播放备注。
- **讲述不照搬原稿**：备注按页整理成自然口播，原稿只作来源。
- **动画用分步页，不用 GIF**：过程演示拆成连续的原生图形分步页加平滑切换，打印成 PDF 时每页都完整。
- **按专业路演水准打磨**：每页一个视觉焦点、内容用满页宽并上下均衡；不用色块小人、线框文件堆等占位图形，卡片统一圆角、细边与轻阴影。
- **版式要 editorial**：浅底、细线、克制配色，不用大块色边或卡片顶部彩色粗边；装饰线能省则省，封面只留主句、产品名与 logo。
- **logo 与品牌名成组**：两者始终放在一起，各页位置一致。
- **截图必须清晰**：用无损 PNG，只裁关键区域、按显示尺寸可读，不把整窗缩小或压成 JPG。
- **流程只画人要做的步**：系统自动完成的事（如选工作流）不画成单独一步，放进备注；流程依赖的核心概念（如草稿、审阅重点）单独讲清。
- **还没有的能力标为计划**：页面上标「计划中」，口播也要说明，不和已上线的功能混在一起讲。
- **路演稿出中英两版**：投资人路演稿同时交付中文版和英文版，内容一致，各用母语读者的说法写，不逐句互译；英文避开「time-poor builders」这类直译腔，按英语投资人的习惯写。
- **路演稿讲正面叙事**：讲已有进展、付费价值、增长路径和积累优势；不写成风险清单，不用「唯一收费点」「待验证、尚无数据」这类自我拆台的收尾，未验证的写成下一阶段目标。
