# Feedback

## General

- **运行画面要连续可信**：办公室镜头要拍到 Agent 进场、到工位并开始工作；门口不动、空白框或其他故障样画面不入片。
- **处理过程要看得见**：点击后有后台处理的步骤（如 Resolve），先展示对应运行日志和处理中状态再给结果；可压缩等待，不可瞬间跳到结果。
- 脚本批准后要求重拍时，先在素材目录外保存恢复清单，再清空旧媒体；旧检查、时长和预览不能证明新一轮可用。
- 真实界面录制用当前环境中任一可用的浏览器工具；先试录核验尺寸、DPR 和真实帧率，合格后再正式采集。试录不合格时保留失败证据，不用静帧拼接或低帧率封装冒充。
- **输入要让观众看清**：录制输入请求的镜头，逐字输入或滚回完整请求并停留到可读；不滚到与脚本无关的区域。
- **动画按脚本做出运动**：脚本写明的动画要做出分层运动，不以两张静帧淡入淡出代替；检查过渡中的每一帧有无重叠，不只看末帧。
- **录屏规格**：分别写明成片尺寸与比例、CSS 视口、DPR、页面缩放和设备布局；画面等比铺满且避开字幕，先全景后推近，不用宽边补比例。
- **录屏动作写满**：每镜写明起始画面、取景、推近目标、逐步动作与输入文字、停顿和结束状态；不跳过中间步骤，每步留够观众看懂的时间。用户没说出口的预期（如从桌面全景开始）也要写成假设交用户审。
- **静帧即成片画面**：画出观众在片中实际看到的那一帧，推近、裁切和位置都按成片来；来源不限（真实界面截图、嵌入真实截图的临时 HTML、收集或模型生成的图），产品界面必须真实。
