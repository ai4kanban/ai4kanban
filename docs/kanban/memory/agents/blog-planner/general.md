# General

## Where the blog lives

- **博客位置**：项目内 `web/content/blogs/`，文章为 `.mdx`，线上地址 `https://ai4kanban.dev/blog/<slug>`。

## Claims

- **只写有依据的说法**：不承诺未经测量的效果，不把我们自己的经验说成读者的情况或普遍规律；有原稿时只用原稿的观点和例子，篇幅不比原稿臃肿。
- **引用要支撑论点**：数据、论文或原句必须直接支撑所在句，仅仅相关就删或换；关于 Agent 能力的判断加 today's 之类的时间限定；社区观点引最直接的原帖，并附原帖截图。

## Structure

- **按读者的问题分节**：每节回答读者会问的一个问题，接住上一节的结论；节标题问 what 就答 what。
- **主题逻辑优先于宣传**：先讲完主题（是什么、现状、痛点、办法、局限），产品只作办法里的例子并写明是举例；不插断主线的宣传节，不加下载号召、自荐内链这类硬广句。
- **标题连贯优先于关键词**：标题、dek、H2 围绕主线，不用「关键词: xxx」式标题；用户给的示例标题只是方向，先评估再提议；措辞贴合主张，不夸大。

## Voice

- **保留人的语气**：润色只修生硬的词，保留短句和停顿，不磨成「专业但像 AI」的顺滑文字；不用似是而非的习语；人与 Agent 对比用 humans，不用 people。
- **说清具体结果**：每句写明对谁、做什么、有什么后果，不写 “walls of text stop working” 这类说不清对什么失效的话；开头用具体真实的场景（如 `/goal` 跑两小时、返工两天）。
- **删赘述不硬缩句**：不写复述上文的总结句，人物第二次出现只写名字；但不压掉主语和衔接，句子要通顺完整。
