# Writing

## Shared

- **润色用户原稿只顺字句**：保留原意和用户特意要讲的概念（如「关键点」「持续学习」），只改标点、生硬词和错字；不改窄意思，不换成口语空话。
- **由一种语言改写成另一种**：写出原文本意，不逐字直译，也不留读不懂的句子；对齐已定稿的那一版，不自行加减论点。
- **中文用正式、易懂的书面语**：不用口语化或生造的说法（如「带你的人」），栏目名用常见的正式叫法（如「导师介绍」）。
- **开头一句话讲清前提**：细节放后面；段首不突然接没铺垫的事；句子短，无歧义。
- **固定说法**：用户可「创建自定义智能体和工作流」（不说「调整角色」）；记忆写「偏好和决策」；数量写「10+ Agent」；AI4Kanban 是工作区，不写成计划生成器。

## Promotional copy

- **定位说「可靠又快」**：AI4Kanban 是多工作流看板（编码、博客、视频等）；可靠来自规划时先预览关键结果，快来自并行执行和交付后的自动跟进。
- **开箱即用是首要卖点**：内置多种专业智能体、工作流和记忆管理，不用自己设计分工或反复调 Prompt；Pro 范围写成小号提示，不夹进正文。
- **卖价值，不卖功能**：先讲用户省下什么——先定交付要求再开工，人只审要点、细节交给智能体，一天交付更多；机制细节留给对比表。
- **对象是有偏向的人群**：面向愿意把执行细节交给智能体、自己把握方向的人，不写「有主见」，不额外强调「通用工具」「不改变工作方式」。
- **规划离不开用户**：不说「全交给智能体」或「一句话→几个问题→计划」；「不用盯着智能体」只限执行阶段，小任务可跳过规划直接实现。
- **编码页的叙事**：一项工作大部分时间在反复改几个关键点，所以一开始就把关键点提到卡片上审完；视觉草稿胜过纯文字的 plan mode，不用开 dev server，拿不准的功能先看草稿再定。
- **草稿从用户的顾虑讲起**：凡是担心 AI 自由发挥的部分都可先出草稿预览、审批后再交付；格式有图片、图表、HTML/TSX、diff、storyboard。
- **记忆和跟进的说法**：每个智能体有按自身场景设计的记忆配方，学用户对特定任务的偏好和决定，智能体间也能共享；跟进写「完成一项主线工作后，智能体自主提出跟进项，帮你补缺补漏」。
- **举产品例子用真实名称**：只列一部分实际的 agent，并链接完整文档。
- **不写自我否定的分析**：如「实测并未显示质量更高」，实测结论只用正面可证的部分。
- **对手写成另一种可行方式**：不贬低，不在对手之间下结论；我们审的是执行前的草稿，不和对手完成后的代码审阅并称「审阅」。
- **对比只写内置有没有**：每项写「有／没有」或「只能…不能…」，不用「另行安排」「取决于配置」绕开；双方都有的（任务拆解、依赖管理、CLI）归共同能力。
- **description／social 写读者想知道的**：为什么值得点开、选谁，不是功能摘要，也不暗示 AI4Kanban 缺共同能力。
- **创始人页讲真实的项目演进**：以用户的故事稿（如 `story.md`）为准，写尝试、反馈和转向；第一人称，可带少量口语；不拿履历代替故事，不编日期、对话或数字。
- **入口先 skill 后应用**：首页和下载区先给可装进各编码智能体的草稿 skill，桌面应用放第二。
- **draft-first 的核心词是「草稿」**：先审草稿，不偷换成「审结果」，也没有「decision」；草稿的意义要接到构建：agent 照确认的草稿做，不漂移。
- **标题讲价值，不列支持的 agent**：支持哪些 agent 用 logo 栏表现；首屏已有的内容（如安装）不再单开一段。
- **落地页说人话**：思路稿、演讲稿只用来理解本质，页面文字要短而准；不把 agent 的内部判断规则或配置细节（如同名文件覆盖）写给访客；一个东西只用一个叫法（如「草稿 agent」，不混 helper）；流程能用图讲就不写长段。
- **FAQ 只收访客真会问的**：如「需要账号或联网吗」这类没人问的删掉。
- **中文大标题不加句末标点**：用换行代替逗号，居中时才对称。
- **草稿只在关键处出**：不写成每个任务都先看草稿，只有需要用户拍板的部分才出草稿，其余由 agent 直接做。

## Docs

- 只说某项能不能设置、在哪设置；不写默认值（如各代理默认 1 小时还是 3 小时）。
