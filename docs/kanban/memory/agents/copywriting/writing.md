# Writing

- **润色用户原稿只顺字句**：保留原意和用户特意要讲的概念（如「关键点」「持续学习」），只改标点、生硬词和错字；不改窄意思，不换成口语空话。
- **由一种语言改写成另一种**：写出原文本意，不逐字直译，也不留读不懂的句子。
- **中文用正式、易懂的书面语**：不用口语化或生造的说法（如「带你的人」），栏目名用常见的正式叫法（如「导师介绍」）。
- **定位说「可靠又快」**：AI4Kanban 是多工作流看板（编码、博客、视频等）；可靠来自规划时先预览关键结果，快来自并行执行和交付后的自动跟进。宣传语要落到具体价值。
- **开箱即用是首要卖点**：内置多种专业智能体、工作流和记忆管理，省去团队架构设计和 Prompt 调优；UI、Prompt、文案只作例子。Pro 范围写成小号提示，不夹进正文句子。
- **草稿从用户的顾虑讲起**：凡是担心 AI 自由发挥的部分，都可先出草稿预览，审批后再交付；格式有图片、图表、HTML/TSX、diff、storyboard。
- **记忆和跟进的说法**：每个智能体有按自身场景设计的记忆配方，学用户对特定任务的偏好和决定，而非通用经验，智能体间也能共享；跟进写「完成一项主线工作后，智能体自主提出跟进项，帮你补缺补漏」。
- **举产品例子用真实名称**：如列出实际的辅助 agent，只列一部分并链接完整文档；数量写「10+ Agent」。
- **同一主题只讲一次**：不在导语、Hero 和后续板块里换词重复。
- **不承诺「一句话→几个问题→计划」**：用户仍要和智能体讨论，小任务也可跳过规划直接实现。
- **草稿审阅不是代码审阅**：我们审的是执行前的关键草稿；对手的完成后代码/分支审阅不能和它并列或混称「审阅」。
- **对比只写内置有没有**：每项写清「有／没有」或「只能…不能…」；不用「另行安排」「取决于配置」绕开；双方都有的（任务拆解、依赖管理、CLI）归共同能力，不写成对手独有。
- **description／social 写读者想知道的**：为什么值得点开、选谁，不是双方功能的 AI 摘要；也不暗示 AI4Kanban 缺共同能力。
- **固定说法**：用户可「创建自定义智能体和工作流」（不说「调整角色」）；记忆写「偏好和决策」（不列「偏好、决定和否决理由」）。
- **不说「全交给智能体」**：规划离不开用户，「你只做决定，其余交给智能体」不能用；「不用盯着智能体」只限执行阶段。
- **下载导语**：「Download AI4Kanban. Plan with precision, ship at speed.」，中文「下载 AI4Kanban，精准规划，快速交付。」

## Docs

- 只写用户想学、会自然问到的内容：能做什么、怎么做、在哪设置；不写内部机制和实现细节。
- 只说某项能不能设置、在哪设置；不写默认值（如各代理默认 1 小时还是 3 小时）。
