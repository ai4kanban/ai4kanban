# 插图风格

## Site figures

- **官网插图**: 水彩底上放白色卡片、软阴影；橙色只标用户审的部分，其余用无字灰条。
- **落地页配图照真实界面画**: 按产品真实样式画，示例素材用已上线的真实内容（如博客封面），不用色块占位；首屏可用录屏，页面不用 GIF。
- **首页工作流预览不手绘**: 直接用卡片页真实的草稿组件，不画仿制的卡片缩影；演示内容只做一套英文版。
- **首页概念图用 3D 动画**: 讲做法的板块（记住意见、主动跟进）不用线稿图，做成斜俯视的看板与卡片浮起的循环 3D 场景，场景内文字只用英文；示例用同一类工作，动作词贴着发生的那一步（Remembered、Applied）。
- **定位概念图一眼看懂**: 只讲一件事，不做多步骤剧情；想法是一句话的气泡，草稿画成极简小卡；不重复下方板块已用的 3D 形式。
- **窗口画全标题栏**: 复刻桌面应用窗口时画出 macOS 红黄绿按钮；界面文字用英文，任务换成产品开发和内容创作的真实例子，不露内部任务和个人路径。
- **记忆不配截图**: 记忆在界面上不外露，只用文字讲。
- **agents 页复用现成录屏**: 优先复用 coding 工作流页的演示录屏；对不上新内容时搭演示看板新拍。
- **README 配图要素净**: 截线上落地页，米白底，不用渐变，暗色主题下也清楚；不放复杂流程图，头部视频讲得清的就不配图；代码写成代码块，不截图。
- **界面图保持原样，但圈出主角**: 不给按钮或字段加标注框；要讲某一栏时，只用一道橙色手绘椭圆圈住它。
- **博客封面**: 左侧三行大号 Georgia 标题（每行约 10 个字符以内），右侧 ✗ 橙粉栏 / ✓ 淡紫栏。
- **文章页配图**: 手绘线稿：简洁的动漫小人配圆头机器人（代表 Agent），纯白底，橙色点缀。

## Hero

- **解决方案页共用 SaaS 页的 3D 首屏**: 不为每页单做。
- **首屏不放背景**: 像素泳道、漂浮 3D 卡片等动态背景都被嫌乱；首屏留白，功夫花在插图上。
- **首屏 3D 要动、要简**: 静图等于没有；不放机器人，只用浅灰和橙色、不用黑色；抽象地画真实界面，不逐项复刻。
- **首屏讲真实流程**: 画产品里真有的一步（卡片展开成卡片页 → 出草稿 → 按执行），不编说不通的动作。

## Agent art

- **角色精灵用代码画**: 按 `kanban-ui/character-design/` 的 README 与 `draw.mjs` 逐像素绘制，48×48 画布，靠头饰与服装区分职业，道具只作辅助。
- **角色动作不烘焙家具**: 角色帧透明、不含桌椅沙发；工作是背身对电脑打字，沙发是正面静止坐姿，叠现有办公室素材核对。
- **服装定稿再铺动作**: 先审全部角色的正背面服装，通过后从正背面读出服装贴到共用动作骨架上，不逐个手画动作。
- **道具一眼看懂，脸要露出**: 道具不挡脸；抽象道具（如立着一页概况的文件夹）被否。
- **交稿前自查**: 与参考图并排、在 96px 和 48px 下看比例和握持，画错就自己重画。

## OG image and logos

- **OG 图**: 深色底，左侧 logo、标题与描边框里的安装命令；右侧要有层次（叠放卡片、批注气泡、确认动作），不只贴一张截图。
- **draft-first logo**: 举剪贴板的动漫风圆头机器人，剪贴板上只画一长一短两条墨线；字标小写 `draft-first`，连字符不着橙色；轮廓不能有刺出的东西，16px 可认，加白色描边以便深色底使用。
