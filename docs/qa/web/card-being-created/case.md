# 等一张新卡片写好

## Setup

- 接 [从首页开始任务](../start-from-home/case.md) 的第 5 步：想法点了「细化想法」，`#1` 刚建好。Runner 是
  假的，领走和写完由脚本触发。
- 第 6 步在项目 `demo-app`：一条质检员提的待筛选项已点「细化想法」。

## Steps

1. 看板上等 Runner 领走。
   预期：`#1` 在「排队中」一列，灰底、无投影，右上「创建中」带小圆点，标题下两条流光骨架线，没有状态
   胶囊和待办。
   证据：[01-queued.png](01-queued.png)
2. Runner 开始写卡，鼠标移到「创建中」上。
   预期：卡片移到「进行中」，提示「正在创建，完成后才能打开」；鼠标不是手型。
   证据：[02-creating.png](02-creating.png)
3. 直接打开 `#1` 的任务链接。
   预期：立刻回到看板，看不到正文和运行日志。
   证据：[03-link-back.png](03-link-back.png)
4. Runner 写完卡片。
   预期：不用刷新，同一张卡片变回普通样式，到「等你处理」，标「待审核」、红色「新」描边。
   证据：[04-ready.png](04-ready.png)
5. 点开它。
   预期：任务页正文已排版（「目标」「重要事项」是标题，看不到 `<!-- agent -->`）；信息栏有
   「创建者 Alice」和「来自对话」链接。
   证据：[05-opened.png](05-opened.png)
6. 打开 `demo-app` 里由质检员的建议变成的 `#8`。
   预期：「创建者」显示质检员图标、名字和来源卡 `#6`，不是点按钮的 Alice。
   证据：[06-by-agent.png](06-by-agent.png)

未取证：写出格式错误的卡片被退回（CLI 的校验，假 Runner 走不到）；创建三次都不合格时的「未能完成」；
再次细化时显示「细化中」。

## Feedback

一眼就知道这张卡还没好，不会点进去看半成品，比以前的白卡片诚实得多。摩擦点：灰卡片点了没任何反应，只有
悬停才说明原因，手机上看不到提示；骨架线一直流动，但不说大概要多久；排队时已经写「创建中」，其实还没人
在写；第 3 步从链接被弹回看板时没有任何提示，分享链接给别人的人会以为链接坏了。
