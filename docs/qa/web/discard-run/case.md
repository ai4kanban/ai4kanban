# 丢弃一次执行，保留任务

## Setup

- 本地云端栈（见 README「如何运行取证」），项目 `demo-app`，假 Runner「QA Mac」。任务：`#5` 待审核、
  `#2` 已停止、`#6` 已完成、`#4` 未能完成。

## Steps

1. 打开 `#5`，点「执行」。
   预期：状态「排队中」；运行日志标题栏最右、竖线之后出现「丢弃这次执行」，日志折叠时也在；标题行不再有
   丢弃按钮，移除图标位置不变。
   证据：[01-queued.png](01-queued.png)
2. Runner 领走构建。
   预期：「执行中 · 0:03」，「丢弃这次执行」还在。
   证据：[02-running.png](02-running.png)
3. 点「丢弃这次执行」。
   预期：日志不展开也不收起；弹窗「丢弃这次执行？这次的改动和工作分支都会清掉。任务和方案保留，可以重新
   执行。」完整显示在标题栏下方，不用先点「停止」。
   证据：[03-ask.png](03-ask.png)
4. 点「丢弃」。
   预期：`#5` 回到「待审核」，方案还在，「执行」回来，运行日志是上一次规划。
   证据：[04-discarded.png](04-discarded.png)
5. 再点「执行」。
   预期：回到「排队中」，可以再次丢弃。
   证据：[05-run-again.png](05-run-again.png)
6. 打开已停止的 `#2`，丢弃。
   预期：丢弃前「已停止」旁有按钮；之后回到「待审核」（接口读回 `waiting_review`，未单独截图）。
   证据：[06-stopped.png](06-stopped.png)
7. 打开已完成的 `#6`。
   预期：运行日志上没有丢弃，也没有移除。
   证据：[07-done-no-discard.png](07-done-no-discard.png)
8. 手机宽度打开未能完成的 `#4`，点「丢弃这次执行」。
   预期：标题栏省掉耗时，只留结果和按钮；弹窗在屏幕内（左右 66–366，屏宽 390）。
   证据：[08-phone.png](08-phone.png)、[09-phone-ask.png](09-phone-ask.png)

未取证：电脑上的改动和工作分支真的清掉、新执行从干净代码开始（假 Runner 没有工作区，见 runner 模块）。

## Feedback

做偏了的执行终于能扔掉重来，而且「丢弃这次执行」贴在那次运行上，单看就懂，再不会和「移除」搞混。摩擦点：
确认弹窗里的按钮又缩回「丢弃」两个字，好在上文写清了；丢弃后日志显示「已完成」，乍看像构建完成了，其实
是上一次规划；页面上看不到清理这一步，只能相信它做了；失败的任务上「重新发起」「续跑」「丢弃这次执行」
三个按钮并列，新用户得想一下区别。
