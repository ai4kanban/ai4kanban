# 在看板上找到待审核的任务并开始执行

## Setup

- 本地云端栈（见 README「如何运行取证」），项目 `demo-app` 放在假 Runner「QA Mac」上。
- 任务 `#4`「订单页支持再来一单」由想法「创建任务」而来，第一步（写方案）已由假 Runner 完成，
  上报了用量和上下文 87k/200k，任务等你批准。`#3` 的卡片上还有一个待答问题。

## Steps

1. 在左栏点「看板」。
   预期：看板分「等你处理」「进行中」「排队中」「搁置」几列，「等你处理」按模块分组；`#4` 标「待审核」。
   证据：[01-board.png](01-board.png)
2. 点 `#4`。
   预期：任务页标「待审核」，右上有「评论」「分享」、移除图标和「执行」；运行日志一行是
   「已完成 · 15 秒 · 约 $0.42」和上下文用量圆环；下面是卡片正文。
   证据：[02-task-page.png](02-task-page.png)
3. 鼠标移到圆环上。
   预期：提示「上下文窗口 87k/200k」。
   实际：提示被运行日志的边框裁掉，只露出圆环上方一条黑边，读不到数字。
   证据：[02-task-page.png](02-task-page.png)（截图时鼠标就停在圆环上）
4. 在手机宽度（390px）打开 `#3`。
   预期：先看到卡片本身（标题、「待审核」、正文），对话不自动铺满；右下「和 AI 讨论」带数字 1。
   证据：[03-phone-card.png](03-phone-card.png)
5. 回到桌面宽度，在 `#4` 点「执行」。
   预期：状态变为「排队中」，「执行」消失；构建交给这台电脑。
   证据：[04-run.png](04-run.png)
6. Runner 开始构建，上报上下文 58k/200k。
   预期：状态「运行中」，运行日志显示「运行中 · 0:10」和圆环，不用等运行结束；右上「停止」。
   证据：[05-live-ring.png](05-live-ring.png)
7. Runner 再上报 121k/200k。
   预期：圆环随之变满（提示里的读数变为 121k/200k）。
   证据：[06-live-ring-grows.png](06-live-ring-grows.png)
8. 在手机宽度打开看板。
   预期：一屏一列，先显示「等你处理 3 个」，右上 4 个页点；底部是「看板」「对话」「更多」。
   证据：[07-phone-board.png](07-phone-board.png)

## Feedback

看板把要我动手的事放在最前，任务页一行就有状态、用时、费用；构建中圆环实时变满，长任务时终于
知道还剩多少余量。手机上先看到卡片再决定要不要聊，比直接弹满屏对话自然。摩擦点：圆环的悬停提示
被裁掉（第 3 步），桌面上读不到数字，手机上本来也无法悬停，圆环的意义只能猜；「执行」仍不说明会
开始构建、占用电脑；任务页正文常要等十几秒才从骨架屏换成内容（本地开发服务器，线上未确认）。
