# 工作区成员打开分享链接

## Setup

- 本地云端栈（见 README「如何运行取证」）。任务「订单页加发票下载」在等审核，有一条「仅受邀的人」的审核链接，
  第 8–14 步用同一任务上「任何拿到链接的人」的链接；
  alice 是工作区所有者，bob 是成员，平时停在自己的工作区。
- 第 3–6、8–14 步里 bob 已走完这台浏览器的首次设置；第 7 步是还没走过的 bob。GitHub 登录由 Auth 替身代答。

## Steps

1. alice 已登录，从首页打开审核链接。
   预期：地址直接换成 `/tasks/<任务>`，是带「分享」、移除、「执行」和「和 AI 讨论」的任务页。
   证据：[01-owner.png](01-owner.png)
2. 按浏览器返回键。
   预期：回到首页，不会回到链接再跳一次。
   证据：[02-back.png](02-back.png)
3. bob 已登录，打开同一链接。
   预期：到任务页，工作区自动切到 alice 的工作区，有移除、「执行」和「和 AI 讨论」。
   证据：[03-member.png](03-member.png)
4. bob 未登录，打开同一链接。
   预期：「你收到一个审核邀请」登录页。
   证据：[04-signed-out.png](04-signed-out.png)
5. 用邮箱验证码登录。
   预期：直接到任务页。
   证据：[05-after-code.png](05-after-code.png)
6. 退出后再打开链接，点「用 GitHub 登录」。
   预期：经 `/auth/callback` 回来，直接到任务页。
   证据：[06-after-github.png](06-after-github.png)
7. 刚受邀、还没连电脑的 bob 打开同一链接。
   预期：直接到任务页。
   证据：[07-no-computer.png](07-no-computer.png)（产品没通过：地址是任务页，但整页被「准备开始 · 连接你的电脑」挡住，
   没有跳过入口，新浏览器还要先过使用情况说明和导览，卡片 #139 待做）
8. bob 未登录，从首页打开「任何拿到链接的人」的链接。
   预期：只读审核页，右上是语言切换和「登录」。
   证据：[08-readonly.png](08-readonly.png)
9. 点「登录」。
   预期：「登录 WildCrane」页，写着「工作空间成员登录后直接进入任务页。」，有 GitHub、邮箱验证码和「返回审核页」。
   证据：[09-sign-in.png](09-sign-in.png)
10. 用邮箱验证码登录。
    预期：直接到任务页。
    证据：[10-link-sign-in.png](10-link-sign-in.png)
11. 按返回键。
    预期：回到首页，不回链接。
    证据：[11-back.png](11-back.png)
12. 退出后从首页再打开这条链接，点「登录」，再点「用 GitHub 登录」。
    预期：经 `/auth/callback` 回来，直接到任务页。
    证据：[12-github.png](12-github.png)
13. 按一次返回键。
    预期：经过链接又立刻跳回任务页，看不到审核页。
    证据：[13-back-once.png](13-back-once.png)
14. 再按一次返回键。
    预期：回到首页。
    证据：[14-back-twice.png](14-back-twice.png)

## Feedback

已登录的成员点链接一步到任务页，返回键也干净，比原来再登录一次的独立站省事；公开链接现在也能在页面上登录，不用另开
应用。摩擦点：新成员最常收到链接，却被首次设置挡在任务外，只想看一眼也得先装桌面端；邀请链接的登录页写「你收到一个审核
邀请」，成员看不出登录后会进任务页，公开链接的登录页才说清楚；GitHub 登录后返回键要多按一次；成员的任务页没有「分享」，
想转发只能找所有者。
