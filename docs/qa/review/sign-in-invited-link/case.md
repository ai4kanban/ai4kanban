# 受邀审核人登录并评论

## Setup

- 本地云端栈（见 README「如何运行取证」）。任务有一条「仅受邀的人」的审核链接，
  carol@example.com 是受邀的人，dave@example.com 不是。
- 本地没有真实邮件，验证码由 Auth 替身固定为 `246810`。浏览器未登录。

## Steps

1. 打开审核链接 `/s/<链接码>`。
   预期：「你收到一个审核邀请」，可用 GitHub 登录，或填邮箱「发送验证码」。
   证据：[01-sign-in.png](01-sign-in.png)
2. 填 `carol@example.com`，点「发送验证码」。
   预期：进入「输入验证码」，写明发到哪个邮箱、10 分钟内有效，有「重新发送」「换个邮箱」。
   证据：[02-code-sent.png](02-code-sent.png)
3. 输入错误的 `111111`，点「登录」。
   预期：六个格子标红，提示「验证码错误或已过期，请重新输入或重新发送。」
   证据：[03-bad-code.png](03-bad-code.png)
4. 改成正确的验证码，点「登录」。
   预期：回到这条链接的卡片，地址不变，右上只有「评论」和自己的邮箱；没有分享、移除、执行和「和 AI 讨论」。
   carol 不是准入账号也能进。
   证据：[04-signed-in.png](04-signed-in.png)
5. 打开「评论」，写一条评论发送。
   预期：右侧评论栏出现这条评论，署名邮箱和时间，计数变为 1。
   证据：[05-comment.png](05-comment.png)
6. 在同一浏览器打开应用首页 `/`。
   预期：不再要求登录（与审核页同一登录态）；账号未准入，显示「这个账号还不能使用 WildCrane。」
   证据：[06-same-session.png](06-same-session.png)
7. 回到链接，从右上邮箱菜单「退出登录」，改用 `dave@example.com` 登录。
   预期：「这个链接仅限受邀的人」，写明当前登录的邮箱，可「换个账号登录」。
   证据：[07-not-invited.png](07-not-invited.png)
8. 以 alice 打开任务页的「评论」。
   预期：carol 的评论在任务页的评论栏里。
   证据：[08-owner-sees.png](08-owner-sees.png)

## Feedback

邮箱验证码一路顺畅，错误提示就地标红，被拒时也说清是哪个邮箱、该怎么办，登录后还停在这条链接上。摩擦点：登录页写
「登录后即可查看预览并给出意见」，但受邀的人只能评论，没有确认或打回的按钮，期望落空；页面不说这个任务是谁发来的、
为什么邀请你，登录后才知道内容；客人点开应用首页只看到「还不能使用」，没有回到审核链接的路。
