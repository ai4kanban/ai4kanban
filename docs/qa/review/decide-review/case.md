# 确认或移除等审核的任务

## Setup

- 本地云端栈（见 README「如何运行取证」），以发起人 alice 登录。三个 Coding 任务在等第一次
  审核，各有任务页和「任何拿到链接的人」的链接；第三个的卡片写了 `blocked_by` 第一个。任务进入待审核由假
  Runner 完成规划作业，没有真实构建，之后 Runner 离线（`cloud.runners.live_until` 改到过去）。

## Steps

1. 打开第一个任务页。
   预期：标题下是「待审核」，右侧有移除图标和「执行」，右下有「和 AI 讨论」。
   证据：[01-owner-open.png](01-owner-open.png)
2. 点「执行」。
   预期：状态变为「排队中」，「执行」消失，运行日志写「排队中，运行电脑连接后开始」，下方有「丢弃这次执行」。
   证据：[02-approved.png](02-approved.png)
3. 鼠标移到「排队中」上。
   预期：提示「等待运行电脑连接」。
   证据：[03-queued-tip.png](03-queued-tip.png)
4. 打开第二个任务页。
   预期：同样是「待审核」，有移除和「执行」。
   证据：[04-second-task.png](04-second-task.png)
5. 点移除图标。
   预期：弹出「移除这个任务？」，原因框占位「原因（可选）…」，下方一行「可以写下原因，以后规划时
   会避开这类任务。」，按钮「不移除」「移除」，弹框里没有「丢弃」二字。
   证据：[05-remove-ask.png](05-remove-ask.png)
6. 在原因框写「先不做，财务那边用不上 CSV」。
   预期：确认按钮仍是「移除」。
   证据：[06-reason.png](06-reason.png)
7. 断网（取证时用浏览器拦下取消请求）后点「移除」。
   预期：弹框收起，页面出现「网络连接已断开，请检查网络后重试。」，任务仍是「待审核」。
   证据：[07-remove-failed.png](07-remove-failed.png)
8. 恢复网络，再点移除图标。
   预期：原因框里还是刚才写的原因，按钮仍是「移除」。
   证据：[08-reason-kept.png](08-reason-kept.png)
9. 把窗口缩到手机宽度（390px），弹框随之关闭；再点移除图标。
   预期：弹框横跨屏幕、左右各留 12px，原因还在，标题、原因框、说明和两个按钮都完整可见。
   证据：[09-phone.png](09-phone.png)
10. 点「移除」。
    预期：状态变为「已移除」，移除和「执行」换成「恢复」，并写明谁何时移除和原因；任务取消并记下原因。
    证据：[10-removed.png](10-removed.png)
11. 打开第三个任务页。
    预期：信息条写「等待」和带锁的第一个任务编号，界面上没有「阻塞」。
    证据：[11-waiting.png](11-waiting.png)
12. 点「执行」，鼠标移到「排队中」上。
    预期：提示「等待 #12 完成」（编号是第一个任务的），不提运行电脑。
    证据：[12-waiting-tip.png](12-waiting-tip.png)
13. 移除第一个任务，再打开第三个任务页，鼠标移到「排队中」上。
    预期：信息条里的「等待」消失，提示换成「等待运行电脑连接」。
    证据：[13-blocker-gone.png](13-blocker-gone.png)
14. 未登录、语言选 English，打开另一张还在等别的任务的卡片的链接。
    预期：只读页的信息条写「WAITING ON」和编号；所等任务移除后，刷新就不再显示。
    证据：[14-visitor-waiting.png](14-visitor-waiting.png)（移除前的画面；移除后只读过页面文字，没有截图）

## Feedback

移除弹框只说一件事：标题和按钮都是「移除」，写不写原因按钮都不变。断网失败时原因还在，不用重写；手机上弹框完整显示，移除后
还能一键恢复。排队原因一悬停就有，还只说眼下要解决的那一件。摩擦点：原因只在悬停时看得到；运行日志已写
「排队中，运行电脑连接后开始」，悬停提示等于重复；说明说「可以写下原因」，却没说不写也能直接移除；失败提示出现在正文里，弹框
已收起，要自己再点开重试；缩窗口时打开的弹框直接消失；「执行」不说明点下去会占用 Runner；移除只是紧挨主按钮的无文字小图标。
