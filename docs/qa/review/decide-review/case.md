# 确认或移除等审核的任务

## Setup

- 本地云端栈（见 README「如何运行取证」），以发起人 alice 登录。两个 Coding 任务在等第一次
  审核，各有任务页。本地没有 Runner，任务进入待审核是直接改库造的。

## Steps

1. 打开第一个任务页。
   预期：标题下是「待审核」，右侧有移除图标和「执行」，右下有「和 AI 讨论」。
   证据：[01-owner-open.png](01-owner-open.png)
2. 点「执行」。
   预期：状态变为「已确认」，「执行」消失；任务回到排队等构建。
   证据：[02-approved.png](02-approved.png)
3. 打开第二个任务页。
   预期：同样是「待审核」，有移除和「执行」。
   证据：[03-second-task.png](03-second-task.png)
4. 点移除图标。
   预期：弹出「移除这个任务？」，原因框占位「原因（可选）…」，下方一行「直接丢弃，或写下原因，
   以后规划时会避开这类任务。」，按钮「不移除」「丢弃」。
   证据：[04-remove-ask.png](04-remove-ask.png)
5. 在原因框写「先不做，财务那边用不上 CSV」。
   预期：确认按钮从「丢弃」变成「移除」。
   证据：[05-reason.png](05-reason.png)
6. 断网（取证时用浏览器拦下取消请求）后点「移除」。
   预期：弹框收起，页面出现「网络连接已断开，请检查网络后重试。」，任务仍是「待审核」。
   证据：[06-remove-failed.png](06-remove-failed.png)
7. 恢复网络，再点移除图标。
   预期：原因框里还是刚才写的原因，按钮仍是「移除」。
   证据：[07-reason-kept.png](07-reason-kept.png)
8. 把窗口缩到手机宽度（390px）。
   预期：弹框横跨屏幕、左右各留 12px，标题、原因框、说明和两个按钮都完整可见。
   证据：[08-phone.png](08-phone.png)
9. 点「移除」。
   预期：状态变为「已移除」，移除和「执行」都消失；任务取消并记下原因。
   证据：[09-removed.png](09-removed.png)

## Feedback

移除弹框比以前干净：一行说明讲清原因的用处，按钮随有没有原因在「丢弃」「移除」间切换，一眼
知道自己在做哪件事。断网失败时原因还在，不用重写；手机上弹框完整显示。摩擦点：失败提示出现在
正文上方，弹框却已收起，要自己再点开重试；「执行」仍不说明点下去会开始构建、占用 Runner，
也没有撤回；移除只是一个无文字的小图标，紧挨主按钮，不易发现。
