# 在 Cloud 看板上，子卡仍在推进的分组不进「搁置」列

## Setup

- **看板**：「Demo Shop」上有三个分组，根卡都是 20 天前写的：#30「结账页改版」的子卡 #31 昨天改过；#40「多语言」的子卡 #41 正在执行，本身 30 天没动；#50「旧报表迁移」整组最近一次改动是子卡 #51，在 9 天前。另有单卡 #21「深色模式」，7 天没动。
- **本次证据的来源**：同 [登录](../sign-in-to-the-hosted-board/case.md) 用例，网站在本地实跑（`next dev -p 3796`），账号和看板由本目录的 [stand-in.mjs](stand-in.mjs) 提供（`node stand-in.mjs 8796 http://localhost:3796`），每张卡的改动时间按「几天前」现算，都是虚构的。无头 Chrome，界面中文，窗口 1800 宽。

## Steps

1. 打开「Demo Shop」看板，跳过导览。
   #30、#40 留在「未就绪」列；「搁置」列只有 #50 和 #21。
   ![](01-board.png)

2. 把鼠标移到 #50 卡脚的「9 天」上。
   提示「9 天没有变动」——天数从组内最近一次改动（子卡 #51）算起，不是根卡的 20 天；#50 排在 7 天的 #21 之前。
   ![](02-stale-days.png)

## Feedback

- **分组终于按整组算**：子卡还在动、或有子卡在执行的分组不会被误判成搁置，「搁置」列里剩下的是真没人碰的事。
- **卡片上看不出为什么没进搁置**：#30 根卡本身 20 天没改，界面不提示「子卡昨天动过」；想知道分组近况仍得点进去看子任务。
- **卡片页不显示所在列**：Cloud 的卡片页没有列名，从看板点进去就看不出它是否属于「搁置」。
- **未在真实 Cloud 上验证**：改动时间来自替身，真实读取是否给每张子卡都带上 `updatedAt` 没有核对过。
