# 在浏览器里打开一个工作区的看板

## Setup

- **账号**：已在 Cloud 看板网站登录（见 [登录](../sign-in-to-the-hosted-board/case.md)），账号能打开两个 workspace；「Demo Shop」上有三张卡：#21 待执行，#22、#23 未就绪。
- **本次证据的来源**：同登录用例，网站在本地实跑，账号、workspace 和卡片由 [stand-in.mjs](../sign-in-to-the-hosted-board/stand-in.mjs) 提供，都是虚构的。浏览器存储在登录前清空，所以这是这台浏览器第一次打开看板。

## Steps

1. 在「你的工作区」里点「Demo Shop」。
   看板打开，第一次会先弹出「功能导览」，五页，可按「跳过」或「下一步」。
   ![](01-tour.png)

2. 按「跳过」。
   看到只读的看板：「待执行」「未就绪」两列，卡片带编号、标题、优先级、ROI 和待办进度；右上角是版本选择、「只读」标记和头像。
   ![](02-board.png)

3. 点 #21「导出发票为 CSV」。
   打开卡片页：标题、状态「可以开始执行」、优先级、ROI、待办进度和正文；顶上有「← 看板」和「在应用中打开」。
   ![](03-card.png)

4. 在地址栏打开一个不属于这个账号的 workspace 地址（`/ws-not-mine`）。
   显示「当前账号无法读取该看板。请使用其所属账号登录，或向其所有者索取链接。」，不透露这个 workspace 是否存在。
   ![](04-not-yours.png)

## Feedback

- **导览挡在第一次打开的看板前**：想看一眼看板的人先得关掉一个五页的弹窗；它在只读的网页版里讲「执行之前先看草稿」等应用里的操作，与眼前能做的事对不上。
- **「只读」说得很清楚**：卡片上没有会改东西的控件，想改的人有「在应用中打开」。
- **列宽固定、卡片挤在右边**：1000 宽的窗口里「未就绪」一列只露出一张半卡片，要横向滚动才看全。
- **未在真实 Cloud 上验证**：看板数据来自替身，真实 workspace 的读取没有核对过。
