# 丢弃一次执行，任务和方案留下

## Setup

- Runner 已登录并在运行（见 [第一次启动 Runner 并登录](../sign-in-and-connect/case.md)），项目
  `demo-app` 已放到这台电脑上，里面有已合入的 DA-3。
- 任务 DA-4（告别函数）已规划完。为了留出点击的时间，它的卡片要求构建时先运行 `sleep 240`。
- 本地云端栈取证，任务页用真实网页；磁盘状态用 `git` 记录。证据里的 `~` 是取证用的临时目录。

## Steps

1. 批准 DA-4，等构建开始。
   预期：DA-4 是「执行中」，电脑上多了工作区和 `card/4/…` 分支。
   证据：[01-building.log](01-building.log)
2. 打开 DA-4 的任务页。
   预期：运行日志的标题栏有「丢弃这次执行」，不用先点「停止」。
   证据：[02-discard-button.png](02-discard-button.png)
3. 点「丢弃这次执行」。
   预期：弹出确认，说明改动和工作分支会清掉，任务和方案保留。
   证据：[03-confirm.png](03-confirm.png)
4. 点「丢弃」。
   预期：运行停下，DA-4 回到「待审核」，按钮变回「执行」，卡片上的方案还在。
   证据：[04-after-discard.png](04-after-discard.png)
5. 查看电脑上的项目。
   预期：工作区和分支都没了，主分支没有变化，卡片还在。
   证据：[05-cleaned.log](05-cleaned.log)
6. 再次执行 DA-4，等它结束。
   预期：新的构建从干净的代码开始，合入主分支。
   证据：[06-run-again.log](06-run-again.log)
7. 对已合入的 DA-3 请求丢弃。
   预期：任务页没有丢弃入口（`discardable: false`），接口拒绝。
   证据：[07-landed-refused.log](07-landed-refused.log)

8. 另一个构建 DA-8 运行时点「停止」，页面显示「正在停止…」时看运行日志。
   预期：「丢弃这次执行」还在。
   证据：[08-stopping.png](08-stopping.png)
9. 点「丢弃这次执行」并确认。
   预期：DA-8 回到「待审核」，工作区和分支清掉。
   证据：[09-after-stop.png](09-after-stop.png)、[10-stop-cleaned.log](10-stop-cleaned.log)

未取证：已经完全停下、未能完成的执行上的「丢弃」，以及电脑离线时等连上再清理；本地栈上没有留出这些状态的时间。

## Feedback

丢弃本身很干净：一次点击，磁盘上不留痕迹，重新执行就是一次全新的构建。不足：按钮叫「丢弃这次执行」，
确认按钮却只有「丢弃」，读得通但不够有把握；丢弃后运行日志一行显示绿色的「已完成」，读起来像这次执行
成功了；「待审核」也不等于用户预期的「等待执行」，只有「执行」按钮说明了下一步。

本地栈上有一处没查清：构建运行中真实点击「丢弃」，请求两次都等了约 56 秒，第三次 90 秒内没到 Worker；其中一次
构建在这期间自己合入，丢弃得到 409，页面也没说明。点击时页面没有任何反馈。「正在停止…」时点击只要 1 秒，
运行中用脚本在页面里发同样的请求只要 0.1 秒。多半是浏览器对本地 HTTP/1.1 的同域连接数限制被运行日志的长连接占满，
线上走 HTTP/2 不一定有，但没有在线上验证。
