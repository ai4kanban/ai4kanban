# 在卡片页看阶段走到哪一步，批准草稿进入下一阶段

## Setup

- **看板**：用本目录的 `seed.sh` 建一个一次性项目：#2「写一篇介绍看板的博客」是博客文章工作流，阶段「大纲、文章」，停在第 1 阶段，大纲已作为 `<Asset>` 放在卡片上，没有待答问题；#3「写一篇讲定期 Agent 的博客」同样停在大纲，还有一道 `[user]` 问题「文章面向谁？」；#4「修好设置页的拼写」是软件开发卡，没有阶段。
- **账号**：本机已登录 Cloud，是 Pro（博客文章是 Pro 工作流）。Cloud 由 [stand-in.mjs](../give-a-copied-video-clone-workflow-a-build-agent/stand-in.mjs) 顶替。
- **Agent**：PATH 最前放本目录的 [stand-in-claude](stand-in-claude)，改名为 `claude`：答已登录，每次运行先把提示词交给 [act.sh](act.sh)。批准 #2 后的那次运行由 `act.sh` 等 8 秒，写出 `article.md`、放到卡片上并勾掉待办，模拟博客策划交付文章。
- **界面**：浏览器打开看板 UI（`kanban-ui`），视口 1440×900（第 5 步 390×844），界面语言中文。截图只截卡片页上半部。

## Steps

1. 打开 `/2`。
   元数据栏（工作流「博客文章」、优先级、ROI、待办项）下面是一条阶段区块：左边「大纲 › 文章」，当前的「大纲」套着浅灰底，「文章」淡色；中间「大纲待你批准」；右边按钮「批准，开始文章」，与工具栏的「修订」一样高（38）。元数据栏里没有单独的「阶段」一项；工具栏只有「修订」「移除」，没有「细化」。
   ![等待批准](01-waiting.png)
   [页面文字与按钮高度](01-waiting.log)

2. 点「批准，开始文章」。
   卡片文件立刻变成 `phase: 2`，下一阶段的运行开始，标题旁写「正在制作下一阶段…」，运行日志展开，按钮消失。阶段区块应当写「正在制作文章…」并把「文章」标为当前；**实际运行期间一直是「大纲」为当前、「正在制作大纲…」**（已报待筛选）。
   ![运行中](02-running.png)
   [每秒的区块文字与卡片文件](02-running.log)

3. 等运行结束。
   阶段区块变成「✓ 大纲 › ✓ 文章」「文章已完成」，没有按钮；卡片上多了「文章」，待办 1/1，工具栏出现「归档」。
   ![文章交付](03-done.png)
   [运行结束后](03-done.log)

4. 打开 `/3`。
   阶段区块是「大纲 › 文章」「1 个问题待你回答」，没有批准按钮；下面是问题面板「文章面向谁？」。
   ![有问题待答](04-questions.png)
   [页面文字](04-questions.log)

5. 打开 `/4`。
   软件开发卡没有阶段区块，元数据栏下面直接是正文；工具栏照旧是「执行」「修订」「移除」。
   ![编码卡片](05-coding.png)
   [页面文字](05-coding.log)

6. 视口换成 390×844，打开 `/3`。
   阶段区块纵向排：上面「大纲 › 文章」，下面「1 个问题待你回答」，占满一行。
   ![手机宽度](06-phone.png)

## Feedback

- **一眼看出该我做什么**：阶段、状态和按钮挤在一条里，「大纲待你批准」加「批准，开始文章」比原来散在三处的「草稿已完成」清楚得多，按钮直接写明批准后做什么。
- **运行中写错阶段**：批准后最需要确认「它在做文章了」，区块却写「正在制作大纲…」，标题旁又是含糊的「正在制作下一阶段…」，两处说法对不上。
- **标题旁的状态不搭**：等批准时标题旁写「可以开始执行」，但博客卡片根本没有「执行」，和区块里的「待你批准」打架。
- **问题选项半中半英**：#3 的问题面板里第三个选项是「Something else — I'll type it」，在中文界面里很扎眼。
- **没有跑到的**：真实博客策划的产出、三阶段卡片的中间阶段、回退到上一阶段、批准被拒（非 Pro、卡片上已有运行）、手机宽度下的批准按钮、英文界面、托管看板上不显示批准。
