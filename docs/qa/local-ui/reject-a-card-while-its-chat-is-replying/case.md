# 卡片的对话还在回复时移除这张卡

## Setup

- **看板**：用 [keep-chatting-while-a-background-task-runs/seed.sh](../keep-chatting-while-a-background-task-runs/seed.sh) 建一次性项目，第三个参数传本目录的 `stand-in.mjs`：新装看板，一张卡 #2「导出 CSV」，看板的 Agent 是 Claude Code。
- **Agent**：`claude` 换成本目录的 `stand-in.mjs`（替身，不连模型、不要账号）。每条用户消息都慢慢回：每 3 秒一句，共 60 秒，再发 `result`；收到 SIGTERM 或 stdin 关闭就退出。dev server 带 `STAND_IN_LOG=<文件>` 时，它把每一句和怎么结束的记进日志。
- **界面**：浏览器打开看板 UI（`kanban-ui`）的 `/2`，窗口 1440×900，界面语言中文。

## Steps

1. 点右上角「讨论」，发「导出 CSV 要注意什么？」，在回复写到第 2 句时停下看操作栏。
   标题旁出现「讨论中」，对话栏末尾是「正在回复」；「执行」「细化」变灰，提示是「对话正在回复，回复结束后即可操作。」；「移除」保持可点。
   ![回复中，移除仍可点](01-replying.png)

2. 不等回复结束，点「移除」，写原因「改由 Cloud 导出，本地不做。」。
   弹出「移除 #2」对话框，和平时一样，没有提到正在进行的回复。
   ![移除对话框](02-reject-dialog.png)

3. 点对话框里的「移除」。
   页面回到看板首页，#2 不在任何列里，「全部卡片」从 2 变成 1。替身在点下的同一秒收到 SIGTERM 退出，只写出了 2 句；卡片的对话文件随之删除。10 秒后归档里的卡片正文没有出现回复的内容。
   ![移除后回到看板](03-after-reject.png)
   [时间线](03-timeline.log)
   [替身的每一句和退出](03-stand-in.log)

4. 再打开 `/2`。
   归档页：「已否决 2026-10-12」，「否决原因」写着「改由 Cloud 导出，本地不做。」；页面上没有讨论栏，也没有那段没写完的回复。
   ![归档里的卡](04-archived-card.png)

## Feedback

- **想丢就能丢**：回复写到一半发现这张卡根本不该做，不用等它说完或先按中止，直接移除，回复当场停下，不会在卡片走后再写回来。
- **对话丢了没提醒**：对话框只说「这张卡片将移出看板」，不提正在写的回复和这段对话会一起丢掉；归档页也看不到它，聊过的内容想留下来只能先手动复制。
- **按钮状态说得清楚**：「执行」「细化」灰掉并说明原因，「移除」亮着，一眼知道此刻能做什么；「修订」也亮着，它的提示说的是打开对话，回复中点它会怎样这里没有试。
- **没有跑到的**：在终端里用 `akb reject` 移除（命令行一侧）、空着原因直接丢弃、交付进行中「移除」变灰、手机宽度都没有在这里验证；回复替身是写死的，真实 Claude Code 被中止时的表现没有对真机核对。
