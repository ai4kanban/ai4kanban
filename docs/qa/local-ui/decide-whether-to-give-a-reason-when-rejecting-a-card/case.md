# 否决一张卡时决定写不写原因

## Setup

- **看板**：一个刚用 `akb install` 建好的看板，界面语言为中文，待办里有一张卡 #2「导出为 PDF」（`akb raw create --title "导出为 PDF" --slug export-to-pdf --body-file <正文>`）。
- **界面**：在浏览器里打开看板 UI（`kanban-ui`）的 `/2`，窗口宽 1280px。第 4 步把机器设置里的 `language` 改成 `en` 并重启看板 UI。
- **不确认**：每一步都停在对话框里，不点「丢弃」或「否决」。

## Steps

1. 打开卡片 #2 的页面。
   操作栏右端是描红边的「否决」按钮，与「开发」「澄清」「修订」分开。
   ![卡片页的否决按钮](01-card-page.png)

2. 点「否决」。
   弹出「移除 #2」对话框：一句「这张卡片将移出看板。」，一个占位符为「否决原因（可选）…」的输入框，输入框下一行提示「直接丢弃，或写下原因，未来会避开这类任务。」；输入框空着时确认按钮写「丢弃」。
   ![空着的否决对话框](02-dialog-empty.png)

3. 在输入框里输入「不在范围内：对外分享走 Cloud。」。
   确认按钮变成「否决」；提示语原样留在输入框下，不随输入变化。
   ![写了原因的否决对话框](03-reason-typed.png)

4. 换成英文界面，再打开 `/2` 点「Reject」。
   对话框标题「Remove #2」，提示是「Discard it, or add a reason so future planning avoids tasks like this.」，空着时按钮写「Discard」。
   ![英文界面的否决对话框](04-english.png)

## Feedback

- **一眼读完**：提示只有一行，两个选择并列，和按钮上的「丢弃」「否决」对得上；不用先弄懂「留空」是什么意思。
- **说了为什么值得写**：「未来会避开这类任务」是写原因的唯一理由，现在就在输入框下面。
- **三个词指一件事**：按钮叫「否决」，标题叫「移除」，空着时确认叫「丢弃」；第一次点进来要停一下才明白这是同一个动作的两种结果。
- **英文占位符在抢话**：「Why are you rejecting this?」默认你在否决，而下面的提示和按钮都说默认是丢弃。
- **没说谁能看到**：原因会原样留在归档卡片上并随看板同步，对话框里看不出来，写的时候不会想到措辞。
- **丢弃的后果没了**：提示不再说丢弃的想法以后可能被重新提出，只写了丢弃的人不知道它会回来。
- **没有跑到的**：没有点确认，否决和丢弃之后的结果不在这个用例里；手机宽度（对话框变成整页）和 `cloud-ui` 里的同一个对话框也没有验证。
