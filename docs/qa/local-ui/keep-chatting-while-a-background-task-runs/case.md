# Agent 的后台任务还在跑时继续对话

## Setup

- **看板**：用本目录的 `seed.sh` 建一个一次性项目：新装看板，一张卡 #2「导出 CSV」，看板的 Agent 是 Claude Code。
- **Agent**：`claude` 换成本目录的 `stand-in.mjs`（替身，不连模型、不要账号）。它照真实 Claude Code 的 `--input-format stream-json --output-format stream-json` 协议说话：从 stdin 逐条读用户消息；消息里有「后台」就先发 `background_tasks_changed`（一项任务）、一句回复和 `result`，15 秒后（有「很久」则 10 分钟）自己发 `task_notification`、一轮回复和 `result`，再发空的 `background_tasks_changed`；别的消息立即回答；stdin 关闭就退出。dev server 带 `STAND_IN_LOG=<文件>` 时，它把收发的每一行记进日志。
- **和真实 Claude Code 的差别**：后台没有真的命令在跑，时长、文案、费用都是写死的；真实 Claude Code 会在后台结束时先发空列表还是先发结论、`task_notification` 的字段，都按卡片 #1540 记的实测写，没有对真机核对。打开看板时看板自己的「描述项目」运行也会交给替身，与本场景无关。
- **界面**：浏览器打开看板 UI（`kanban-ui`），窗口 1440×900，界面语言中文。

## Steps

1. 打开 `/2`，点右上角「讨论」打开对话栏，发「在后台跑一下 npm test」。
   约 2 秒内回复结束（「已在后台开始跑 npm test，跑完我再告诉你结果。」），输入框可以继续输入；输入框上方出现带脉动圆点的「1 个后台任务进行中 · 中止」。
   ![后台任务在跑](01-background-running.png)

2. 不等后台结束，再发「导出按钮放哪？」。
   约 0.2 秒就得到回答（「可以，后台任务不影响回答：……」），后台任务行仍在；替身日志里两条消息进的是同一个进程。
   ![后台在跑时照常回答](02-answer-while-running.png)
   [时间线](flow-1.log)

3. 等后台任务结束（发出第一条后约 15 秒）。
   结论「后台的 npm test 跑完了：42 项测试全部通过。」作为单独一条出现在对话末尾，上方折叠行写「后台任务结束后」；后台任务行消失。展开折叠行能看到「后台命令 npm test 已结束」。
   ![后台结论单独成条](03-result-after-background.png)
   ![展开「后台任务结束后」](03b-fold-opened.png)

4. 再发「再在后台跑一个很久的」。
   回复结束后，输入框上方又出现「1 个后台任务进行中 · 中止」。
   ![第二个后台任务](04-second-background.png)

5. 点「中止」。
   约 0.5 秒后后台任务行消失，对话末尾没有新的「后台任务结束后」；替身进程收到 SIGTERM 退出。
   ![中止之后](05-stopped.png)
   [时间线](flow-2.log)
   [替身收发的每一行](06-stand-in-protocol.log)

## Feedback

- **不用干等**：后台任务在跑时回复照常结束，输入框不锁，再问立即有答；这是这次改动最实在的好处。
- **结论位置靠折叠行认**：结论排在后来的问答之后，「后台任务结束后」这行字很小、和「用时 x 秒」同一个样式，扫一眼容易当成普通回复，想不起它回答的是哪一句。
- **任务行只有数字**：「1 个后台任务进行中」不说是什么任务、跑了多久；有两个以上时分不清。
- **「中止」没有确认，也没有痕迹**：点下去后台任务立刻没了，对话里不留一句「已中止」，回头看不出那个任务是被停掉的还是没结果。
- **没有跑到的**：真实 Claude Code；后台等待 2 小时上限；卡片运行（非对话）里的后台等待；在回复还在写时点「中止」；终端里的 `akb chat`；英文界面。
