# 打开待筛选，看条目是谁写的，再回到原来的页面

## Setup

- **看板**：用本目录的 `seed.sh` 建一个一次性项目：新装看板，一张卡 #2「导出 CSV」，看板的 Agent 换成本目录的 `stand-in.mjs`（不连模型：作为 `qa-manager` 启动时执行一次 `akb triage add`，别的运行什么都不做）。待筛选是空的。
- **界面**：浏览器打开看板 UI（`kanban-ui`），窗口 1440×900，界面语言中文。
- **切换程序**：无头浏览器没法真的切到别的程序，第 5–7 步用页面上的 `window` `blur` / `focus` 事件代替，和卡片 #1517 的验证方式相同。

## Steps

1. 打开卡片页 `/2`。
   顶栏右侧的收件箱图标就是「待筛选」，没有数字。
   ![卡片页](01-card-page.png)

2. 点「待筛选」。
   进入待筛选页，按钮变成按下的样子。「待处理 0」下面只有图标、「暂无待筛选条目」和一行说明，没有「从接口拉取」「查看历史」链接。
   ![空的待筛选](02-empty-triage.png)

3. 再点一次「待筛选」。
   回到刚才的卡片页 `/2`。
   ![回到卡片页](03-back-to-card.png)

4. 直接打开 `/inbox`，再点「待筛选」。
   没有来处可回，回到看板首页 `/`。
   ![回到看板](04-back-to-board.png)

5. 离开窗口，在终端加一条待筛选。
   终端回 `added to triage: docs/kanban/triage/csv.md`。
   ![离开前的顶栏](05-before.png)
   [`akb triage add` 的输出](06-triage-add.log)

6. 15 秒内不回到窗口。
   顶栏的「待筛选」仍然没有数字。
   ![还没回来时的顶栏](07-still-away.png)

7. 回到窗口。
   不用刷新，「待筛选」立刻变成红底的「1」。
   ![回来后的顶栏](08-after-switch-back.png)

8. 在终端让 QA 管理员立即运行一次：`akb workflow schedule coding --run qa-manager`。
   运行马上结束，它往待筛选里写了一条。
   [命令输出](09-run-qa-manager.log)

9. 打开待筛选页。
   两条分两组：QA 管理员写的那条来源一栏是「qa-manager」，排在前面；终端里加的那条是「未注明来源」。
   ![按来源分组](10-grouped.png)

10. 点「全部来源」。
    菜单里有「全部来源」「qa-manager」「未注明来源」三项。
    ![来源筛选](11-source-filter.png)

11. 关掉菜单，点 QA 管理员写的那条。
    右侧详情顶上写「qa-manager · 10月4日 16:42」。
    ![条目详情](12-item.png)

## Feedback

- **开关顺手了**：「待筛选」现在和铃铛、讨论一样再点一次就收起，回到的正是刚才那张卡；直接打开地址时回首页也合理。
- **空状态干净**：只剩一句话，没有点了也没用的链接。
- **切回窗口就有新数字**：终端里加的条目不用切页就出现在顶栏，不过只有真的离开过窗口才会刷新——一直开着看板等，数字不会自己变。
- **`--source` 写了等于没写**：终端里明明写了 `--source "用户邮件"`，列表、筛选和详情都说「未注明来源」；这句原文只在条目文件里。用户会以为参数没生效。
- **Agent 名直接露出来**：来源写的是 `qa-manager` 这个内部名，而配置里它叫「QA 管理员」；能看出是谁，但两处叫法不一致。
- **没有跑到的**：真实桌面应用里切换程序；手机宽度的顶栏；英文界面；页内 iframe 获得焦点时不刷新。
