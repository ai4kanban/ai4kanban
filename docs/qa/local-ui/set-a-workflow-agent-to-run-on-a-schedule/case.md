# 在工作流里让一个 Agent 定期运行

## Setup

- **看板**：一个刚用 `akb install` 建好的看板（项目是 git 仓库），删掉 `docs/kanban/setup-checklist.md`，界面语言为中文；工作流是内置的「软件开发」，还没有自建 Agent，也还没有完成过卡片。
- **Agent**：用 [`skill/run-a-workflow-agent-on-a-schedule/stand-in.mjs`](../../skill/run-a-workflow-agent-on-a-schedule/stand-in.mjs) 顶替真实的 Agent（不需要账号），写法见那个用例的 Setup；被定期运行启动时它往 `CHANGELOG.md` 加一行。
- **界面**：这次构建的 `kanban-ui`（`AI4KANBAN_CLI` 指向这次构建出的 `cli/dist/kanban.mjs`），在浏览器里打开看板，窗口 1280×1000。截图只截「配置」或「运行历史」窗口。
- **英文界面（第 15、16 步）**：把界面语言换成 English 后重开同一个看板。

## Steps

1. 点右上角的「配置」，再点左栏的「工作流」。
   「规划」「执行」两个分组框下面是「定期运行」框，小字「按时自动运行，与卡片无关」，右端一个「+」，下面已经有一个 Agent：「质检员」。
   ![定期运行框里自带质检员](01-scheduled-box.png)

2. 点「质检员」。
   右侧名称行有两个控件：周期小控件「自动」和「立即运行」，没有「删除」；描述「维护项目的测试用例：跟进每张完成的卡片，并为已有功能补写场景。」再往下是「运行时」和一个「额外要求」框，框右上角标着「软件开发 · 定期运行」；没有 `AGENT.md`，也没有上次或下次运行的时间。
   ![质检员的页面](02-qa-manager.png)

3. 点周期小控件「自动」。
   菜单第一行灰字「下次运行 6 小时后」；「自动」打勾，下面一行浅色小字「有卡片完成后，最多每 6 小时一次」；然后是「每 6 小时」「每天」「每 7 天」「自定义」，分隔线下面是棕红色的「停用」。
   ![自动一项带说明](03-auto-explained.png)

4. 按 Esc 关掉菜单，点进「额外要求」框，输入「场景一律用中文写。」，再点框外。
   文字留在框里；没有「已保存」之类的提示（第 15 步换成英文重开后它还在）。
   ![写了额外要求](04-extra-requirements.png)

5. 点「定期运行」框里的「+」。
   「质检员」下面出现新建行：名称输入和「创建」，行下小字「小写字母，用短横线连接」。
   ![定期运行的新建行](05-new-agent-row.png)

6. 输入 `changelog-keeper`，按回车。
   框里多出「Changelog keeper」并被选中。右侧名称行是「你添加的」标签、周期小控件「自动」、「立即运行」、「删除」；下面是它的 `AGENT.md`，写着 `hook: schedule`，没有「额外要求」框。
   ![新建的周期 Agent](06-created.png)

7. 点周期小控件「自动」。
   「自动」打勾，它下面的小字是「每天一次」——这个 Agent 不等任何输入；其余选项与第 3 步相同。
   ![新 Agent 的周期菜单](07-cadence-menu.png)

8. 选「每 6 小时」。
   菜单收起，小控件变成「每 6 小时」。
   ![改成每 6 小时](08-every-6-hours.png)

9. 点「立即运行」，等它变回来后再点小控件。
   按钮先变成不可点的「正在运行…」，几秒后变回「立即运行」；项目里多出一个提交 `changelog-keeper: scheduled run (Coding)`。菜单第一行变成「下次运行 6 小时后」，打勾的是「每 6 小时」，「自动」下面仍是「每天一次」。
   ![运行之后的菜单](09-ran.png)

10. 关掉「配置」，点右上角的「运行历史」，再点场景里标着「Changelog keeper / 定期运行」的小人。
    展开的面板标题是「软件开发 · Changelog keeper」，右边写着「定期运行」、开始时间和对勾；正文「Added one line to CHANGELOG.md.」。
    ![运行历史里的这一遍](10-runs.png)

11. 回到「配置 → 工作流」，选中「Changelog keeper」，点周期小控件，选「停用」。
    小控件变成「已停用」，「立即运行」仍可点；左边它移到「质检员」下面的「已停用（1）」小标题下，头像变灰。
    ![停用之后](11-disabled.png)

12. 点「立即运行」。
    按钮变成「正在运行…」，几秒后变回来，小控件仍是「已停用」；项目里又多一个同名提交——停用只停了定时，不挡手动运行。
    [12-ran-while-disabled.log](12-ran-while-disabled.log)

13. 再点小控件「已停用」。
    菜单里是全部七项，「停用」打勾；「自动」下面仍是「每天一次」；没有「下次运行」那一行。
    ![停用时的菜单](13-menu-while-disabled.png)

14. 选「自动」。
    Agent 重新启用：小控件是「自动」，左边回到「质检员」后面，「已停用」小标题消失；再打开菜单，第一行「下次运行 23 小时后」，「自动」打勾。
    ![重新启用为自动](14-enabled-on-auto.png)

15. 用英文界面打开同一页，点「QA manager」。
    框叫「Scheduled」，小字「Runs on its own, not per card」；控件是「Auto」「Run now」，下面的框叫「EXTRA REQUIREMENTS」，范围「Coding · Scheduled」，里面还是第 4 步写的那句话。
    ![英文界面](15-english.png)

16. 点「Auto」。
    第一行「Next run in 6h」；「Auto」打勾，下面「After a card is finished, at most every 6h」；然后「Every 6 hours」「Every day」「Every 7 days」「Custom」「Disable」。
    ![英文的周期菜单](16-english-menu.png)

## Feedback

- **「自动」终于说清了**：以前菜单里只有「自动」两个字，现在一眼就知道质检员要等卡片完成、最多 6 小时一次，自建的那个每天一次；不用去翻文档。
- **「下次运行 6 小时后」会误导**：一张卡都没完成时，质检员的菜单照样写「下次运行 6 小时后」，紧接着下面一行却说要「有卡片完成后」才跑；6 小时后它其实不会跑。两行要合起来读才对。
- **「自动」和预设重复**：自建 Agent 的「自动」就是「每天一次」，和下面的「每天」是同一回事；选哪个都一样，看不出「自动」多了什么。
- **英文写法前后不一**：说明里是「every 6h」，紧挨着的选项是「Every 6 hours」，第一行又是「Next run in 6h」；中文没有这个问题。
- **停用后仍能手动运行，现在是诚实的**：「立即运行」可点，点了也真的跑，提示与行为一致；停用的含义只是「不再按时自己跑」，这一点界面上没写，但不难猜。
- **名称两种语言差得远**：中文叫「质检员」，英文叫「QA manager」，描述里又说「测试用例」；在中英文之间切换的人会以为是两个 Agent。
- **新建完是个半成品却能马上跑**：`AGENT.md` 还是「Unwritten — …」的英文占位，「立即运行」已经可点；新建后默认「自动」、每天一次，明天这时它就会带着占位规则自己跑一遍。
- **运行中看不出进度**：按下后只有「正在运行…」，结束后页面上没有上次运行时间，也不提这一遍有没有改动、提交是哪个；要去「运行历史」或 `git log` 才知道。
- **「额外要求」存没存看不出来**：失去焦点就保存，没有任何反馈。
- **「停用」藏在周期菜单里**：要先想到「停用是一种周期」才会去点周期小控件。
- **没有跑到的**：质检员的「立即运行」（替身不做它的事）；「自定义」周期的编辑区；运行失败后的界面；手机宽度。看板自带的定期 Agent 见 [看板自带的 Agent 在「自动」下多久跑一次](../see-when-the-board-s-own-agents-run-on-auto/case.md)。
