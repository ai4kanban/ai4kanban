# 在执行中的卡片上看「差异」，合入后在归档页再看一次

## Setup

- **看板**：用本目录的 `seed.sh` 建一个一次性项目：首个提交里有一行的 `README.md`，新装看板，卡 #2「导出 CSV」写好了摘要和一条未勾选的待办，提交模式是默认的自动提交。
- **Agent**：看板的 Agent 换成本目录的 `stand-in.mjs`（不连模型）：收到「实现」后先等 20 秒，再改 `README.md`、新建 `src/export-csv.js`，什么都不提交，然后一直等到它旁边出现 `finish` 文件才结束——相当于一次还在写的构建。
- **界面**：浏览器打开看板 UI（`kanban-ui`）的 `/2`，窗口 1440×900，界面语言中文。

## Steps

1. 按「执行」，在确认框里勾选「我知道方案可能还不完善」，按「仍然执行」；马上点「差异」。
   标题旁出现「正在执行…」，「差异」页签只有一行「还没有改动」，下面是 `card/2/… → main` 和「自动提交」。
   ![还没有改动](01-no-changes-yet.png)

2. 等 Agent 写完文件（约 25 秒）。
   交付的工作区里有一个改动的文件和一个新目录，分支上还没有新提交。
   [工作区状态](02-worktree-status.log)

3. 点「日志」，再点回「差异」。
   不用刷新页面就看到「2 files changed, 8 insertions(+)」：新建的 `src/export-csv.js` 带「新增」标记，`README.md` 多了四行。没有「未提交」之类的标记。
   ![执行中的改动](03-uncommitted-work.png)

4. 让 Agent 结束（`touch finish`）。
   看板提交并合入，`main` 上多了「导出 CSV (#2)」一个提交，卡片被归档。
   [main 的提交](04-landed.log)

5. 打开归档页 `/archive/2`（重新打开 `/2` 也是这一页）。
   正文下面有默认展开的「差异」区块，只有「差异」一个页签、没有按钮，内容和第 3 步相同；底栏写「已合入 <提交>」和「MAIN」。
   ![归档页的差异](05-archived-diff.png)

## Feedback

- **终于看得到 Agent 在写什么**：执行中的「差异」直接反映工作区，包括没提交的新文件，不必等运行结束或去终端翻 git。
- **要手动重开页签**：差异不会自己更新，停在「差异」上看到的是打开那一刻的内容；不知道要点「日志」再点回来的人，会以为 Agent 什么都没写。
- **归档页补上了「改了什么」**：合入后卡片立刻归档，现在归档页就能看到这次交付的改动和合入的提交号，不用去 `git log` 查。
- **没有跑到的**：英文界面；手动提交模式；只产出文件的工作流；合入提交已不可读时的说明；评审阶段的差异。
